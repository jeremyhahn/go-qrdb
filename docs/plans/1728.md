# Plan: #1728 — gate the FIPS strict floor on feature activation

## Objective

Under FIPS-140, `lifecycle.ApplyFIPSIsolationFloor` commits the strict
cluster isolation floor at start-up. It must first wait, bounded by the
start-up context, until the strict-isolation and guarded-writes cluster
features are active, as the normal floor path does (owner decision 11-25,
#1576 Q2). Standalone (no Raft) has every feature active at once; raft
activates once every member advertises (ruling 1350). No compat code
(ruling 1354).

## Slices

1. Prove the first-boot activation order.
   - `TestGate_FirstBootActivationOrder` in
     `pkg/cluster/featuregate/featuregate_test.go`: on a single node and on
     three nodes, guarded-writes activates before strict-isolation.
   - Section "First-boot feature activation order" in
     `docs/clustering/engineering.md`.
2. Gate the FIPS floor.
   - `ApplyFIPSIsolationFloor` returns at once when the floor is already
     strict, otherwise waits for `tenant.RequireStrictIsolation` to pass,
     then writes strict. A ctx cancel first returns
     `ErrFIPSFloorNotStrict` wrapping the missing feature.
   - Tests in `pkg/server/lifecycle/isolation_floor_test.go`: late
     activation writes nothing before activation; a standalone (active)
     composition is strict at once; ctx cancel refuses with
     `ErrFIPSFloorNotStrict` and no write.
3. Bound the FIPS floor's feature wait (PR #1741 sdk/go/node hang).
   - The wait is bounded by the start-up floor wait (`defaultFloorRetry.wait`,
     30 s) as well as ctx, since cmd/qrdbd and the SDK pass a ctx only a
     signal ends.
   - `TestApplyFIPSIsolationFloor_BoundsFeatureWait`: on a ctx that never
     ends, standalone is strict at once, raft is strict once every member
     advertises and refused within the bound otherwise.
   - The SDK weak-floor double reports the features active, so the test
     reaches the refused tightening; it runs on a bounded ctx.
   - The SDK clustered boot started its feature gate and member record
     only after `wireClientAndServer`, whose floor waits for features those
     advertise: every FIPS clustered boot deadlocked. `wireClientAndServer`
     now starts both right after the feature client, before the floor, as
     cmd/qrdbd starts its gate first; the failure branches stop them.
4. Coverage (CI coverage-merge, #1741): table-driven tests lift
   pkg/api/grpc to >= 93.5% (GetUserByEmail, DatabaseScale, barrier
   status mapping, group/vector nil-service paths) and pkg/auth/wiring to
   100% (FirstAdminPins, TenantStatusReader with and without the
   isolation-policy reader, GroupResolver). Tests only.
5. Codex round-7 P1s: the node-key probe lists only the node-local vector
   store (home-only tenant tightens); a reclaimed create keeps the
   successor's dirs; vector DeleteNamespace persists a retired sweep key
   until done (retry/Compact drain it); home stores seed vector metrics.
