# #1478 — user update, disable/enable and cert bindings in the UI, against a real server

## Objective

The admin UI drives every user operation the backend offers, proven by a
DOM-tier Playwright spec against a live qrdbd: update, disable, enable,
add/remove a certificate binding, and look a user up by certificate
thumbprint.

## Findings at the base

- `UserDetail.svelte` only called `users.update`; it had no disable/enable
  or certificate-binding controls.
- `UserManager.svelte` had no lookup by certificate thumbprint.
- The SDK `User` type did not carry `certBindings`, although the REST
  server returns `cert_bindings` on every user.

## Slices

1. SDK: `User.certBindings?: readonly CertBinding[]` (thumbprint, kind,
   notAfter), exported from the package index.
2. UserDetail: Account Status card (lifecycle badge, Disable/Enable) and a
   Certificate Bindings card (list, add by SPKI thumbprint with optional
   expiry, remove). Errors surface the server's message in a toast.
3. UserManager: "Find by certificate thumbprint" field that opens the
   matching user, or reports that no user holds the binding.
4. `e2e/dom/user-detail-roundtrip.spec.ts` (seal "none"):
   - create a user, rename it in UserDetail, check GET /v1/users/{id};
   - disable then enable; check the server lifecycle and the UI badge;
   - openssl self-signed cert -> SPKI SHA-256 thumbprint; add the binding
     in the UI, check the server lists it, look it up in UserManager,
     remove it, check the lookup now finds nobody;
   - a malformed thumbprint is refused and the server's error shows.

## Departures found while building

- The fixture's seal "none" no longer boots (server: auth.enabled requires
  seal.enabled), so the spec uses "none-committed" and initializes through
  POST /v1/ceremony/initialize (so_pin, user_pin, admin_generate).
- Create User was refused by the server (email required) because the form
  and the SDK request types had no email: the SDK Create/UpdateUserRequest
  and User gain email and name, and UserDetail gains Email and Display Name.
- The users routes are unprefixed (/users/...), not /v1/users.

## Out of scope

Go server code, docs/SPEC.md, docs/gui/coverage-matrix.md, rest.ts.
