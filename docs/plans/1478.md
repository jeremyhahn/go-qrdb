# #1478 — every backend operation the UI reaches, proven by Playwright

## Objective

The desktop/web UI drives each SDK operation listed in
docs/gui/coverage-matrix.md, and a Playwright spec proves each one. The
work ships in PRs of at most three gap groups (DS-8567 split of #1479).

## Done in earlier parts

- User update, disable/enable, certificate bindings and lookup by
  thumbprint (UserDetail, UserManager), proven by
  `e2e/dom/user-detail-roundtrip.spec.ts` against a live qrdbd (seal
  "none-committed", initialised through POST /v1/ceremony/initialize;
  the users routes are unprefixed /users/...).
- Part 1 (#1497): gap groups 1 (database settings) and 3.

## This part: gap groups 6, 7, 8 (replayed from lane/gui1478a)

1. Group 6, volume pools:
   - Go: `VolumePoolBinding` (List, Get, Create, Update, Delete,
     ListTenants) registered in the desktop bindings; unit test
     `bindings_volume_pool_test.go`, binding count test updated.
   - SDK wails.ts: `volumePools` served by the binding (was
     NotImplementedError).
   - UI: `views/admin/VolumePoolManager.svelte`, an Admin nav entry and
     route, and a pool picker on the create-tenant form.
   - Mock: VolumePoolBinding store in fixtures/wails-mock.ts.
   - Tests: `e2e/admin-volume-pools.spec.ts`,
     `e2e/dom/audit-volume-pools.spec.ts`, binding smoke list.
2. Group 7, tenant trust and holders:
   - TenantDetail shows why the trust-anchor list failed to load, not an
     empty list; TenantManager enrols a tenant share holder
     (`officers.registerTenantOfficer`).
   - Tests: `e2e/tenant-trust-anchors.spec.ts`,
     `e2e/dom/tenant-trust-roundtrip.spec.ts`, two cases in
     `e2e/tenant-holders.spec.ts`.
3. Group 8, vector: VectorView gains batch upsert/delete, get vector,
   hybrid search and metadata update.
   - Tests: `e2e/vector-advanced.spec.ts`,
     `e2e/dom/vector-advanced-roundtrip.spec.ts`.

Each group marks its coverage-matrix rows covered.
