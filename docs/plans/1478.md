# Plan: admin Settings view against a real server (#1478)

## Objective

The admin Settings view (`cmd/qrdb/frontend/src/views/admin/Settings.svelte`)
shows values that match the server and its Disconnect action works, proven by
a DOM-tier Playwright spec against a real qrdbd
(`e2e/dom/settings-roundtrip.spec.ts`, `playwright.dom.config.ts`).

## Slices

1. DOM spec, seal "none" daemon:
   - About table `server` row equals the server's `/status` `node_id` (what
     the REST SDK's `connection.getVersion()` reports; qrdbd has no separate
     version route), `sdk` row is non-empty.
   - Connection badge reads Connected; Server card's Initialized matches
     `GET /v1/config/initialized`; Embedded server available is No (REST).
2. Disconnect from Settings: badge reads Disconnected, the button disables,
   the server still answers `/health`; the header Connect button reconnects
   and the badge reads Connected again; a fresh page load also connects.
3. UI fix (own commit): web-mode `connectProfile` reopens a REST transport
   closed by `connection.disconnect()` (Settings' Disconnect left the app
   stuck until a reload), and Settings re-reads
   `client.connection.isConnected()` when the active profile's connection
   state changes, so a reconnect while the view is open shows Connected.

## Out of scope

- Server (Go) changes, SDK changes (`sdk/typescript/src/rest.ts` is owned by
  another lane), a server version route.
- docs/SPEC.md and docs/gui/coverage-matrix.md (coordinator).
