# Plan: tenant update and delete against a real server (#1478)

## Objective

The admin UI's tenant update (`views/admin/TenantDetail.svelte`,
`client.tenants.update`) and tenant delete (`views/admin/TenantManager.svelte`,
`client.tenants.delete`) are driven end to end against a live `qrdbd` in the
DOM tier, with the server state checked over the REST API.

## Slices

1. `cmd/qrdb/frontend/e2e/dom/tenant-update-roundtrip.spec.ts`, booted like
   `tenant-management.spec.ts` (`startDaemon({ seal: "none" })`):
   - update: create a prefix tenant, open it, rename it in the info card,
     Save, expect the `Tenant "<id>" updated.` toast, the field shows the new
     name and `GET /v1/tenants/{id}` returns it;
   - refused update: pick an isolation type the single-node, no-seal server
     cannot provision, Save, expect an error toast carrying the server's
     error, and `GET /v1/tenants/{id}` still reports `prefix`;
   - delete: select the tenant row in the Tenants list, Delete Selected,
     confirm the dialog, expect the `Deleted 1 tenant.` toast, the row is
     gone from the UI and `GET /v1/tenants` no longer lists it while
     `GET /v1/tenants/{id}` is 404.
2. A UI defect the spec exposes is fixed in its own commit in the view.

## Tests

`npx playwright test --config=playwright.dom.config.ts
e2e/dom/tenant-update-roundtrip.spec.ts`; `npm run check` 0 errors.

## Out of scope

Go server code, the SDK, `docs/SPEC.md` and `docs/gui/coverage-matrix.md`
(the coordinator updates the matrix row), the real-backend API-only tier.
