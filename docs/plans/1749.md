# #1749: run the multi-node cluster suites on every pull request

## Objective

No multi-node test ran on an unlabelled pull request: the three-node
self-spawned suites `clustering` and `cluster-verification` ran only in the
full-tier `integration-features` shards (2 and 5). A pull request must form a
Raft cluster before it merges, so both move to one code-tier job,
`integration-cluster`, and each still runs once per run.

## Slice 1 (ci1749a)

- ci.yml: new job `integration-cluster` (`Integration (cluster)`) after
  `integration-features`: the code-tier `if:` with the draft skip, needs
  `docker-build`, `test-typescript`, `preflight`, 120-minute limit, the
  shards' steps (masks, disk, LAN pull, artifact download and retry, load,
  `make integration-test-features`, `always()` teardown, prune), project
  `qrdb-ci-<run>-<attempt>-cluster`. The feature list is the job env's
  `IT_FEATURES: clustering cluster-verification`, so the test step is the
  shards' command verbatim (one test-step shape for every leg).
- Shards 2 and 5 drop `clustering` and `cluster-verification`.
- ci-gate: `integration-cluster` in `needs`, `RESULT_INTEGRATION_CLUSTER`,
  `check integration-cluster ... code`.
- test/buildgates/feature_jobs_gate_test.go: coverage across the shards plus
  the cluster job's list (every feature in exactly one leg); the cluster job
  held to the shards' step, image, teardown and project rules, in the code
  tier, with no matrix. Fixture gains a cluster job; failing cases for a
  feature in a shard and the cluster job, a duplicate, an unknown name, an
  empty or expression list, a full-tier or sharded cluster job, a shared
  project, no limit, no `always()` teardown, a fixed list, the wrong artifact.
- ci_tiers_test.go `codeTierJobs`, ci_logs_test.go `credentialJobs`,
  ci_image_digest_test.go `digestConsumersWant` gain the job.
- docs/release/architecture.md (CI tiers) and engineering.md (job lists,
  shard table) updated.

Tests: `go test ./test/buildgates/ -run 'IntegrationFeatureCoverage|CIGate|
CITier|CILogs|CIImageDigest|CIRunners|IntegrationJobNames'`,
`make check-integration-feature-coverage`, `make check-action-pins`,
`make lint-workflows`. The suites need Docker: the PR's CI run
(`Integration (cluster)` green, PASS lines for both) is the proof.

## Out of scope

docs/SPEC.md, pm/rows.md, go.mod, the Makefile, features.mk, integration
test files, other workflows, the soak job, rebalancing the shard table's
expected times (next full-tier run's PASS lines).
