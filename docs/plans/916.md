# Plan: #916 — SPEC row `arm64-release`

## Objective

SPEC row `arm64-release` (docs/SPEC.md): linux-arm64 and linux-arm64 FIPS
artifacts from the release workflow; the integration suite run once on
arm64 before the RC. The row PR marks the row shipped in docs/SPEC.md and
closes #916.

## Status

Done on main:

- `release.yml` builds qrdbd and the headless qrdb CLI for linux/amd64 and
  linux/arm64, plain and FIPS (`make release-artifacts`,
  `RELEASE_PLATFORMS=linux/amd64 linux/arm64`); docs/release/user.md lists
  the four arm64 artifacts.
- CI's full tier runs `make release-cross PLATFORM=linux/arm64` (plain and
  FIPS), so a broken arm64 build fails before the tag.
- `make test-cross PLATFORM=linux/arm64` compiles the root, `sdk/go` and
  `test/clusterproof` test binaries for arm64, plain and FIPS; its own
  behaviour is pinned by `make test-test-cross` in the lint gates. It
  passes on main 497ed95ef (this lane, 2026-11-13, on an amd64 host).

Remaining (blocked):

- One `make test-cross PLATFORM=linux/arm64 && make integration-test` run
  on a linux/arm64 host from a clean checkout of the RC candidate commit
  (docs/release/engineering.md, "linux/arm64 before the RC"). It needs:
  1. the RC candidate commit, which follows rows 21–24 (triage DS-3461);
  2. an arm64 host with Docker. The lane container is x86_64 with no
     Docker and no arm64 emulation; a CI arm64 job is a `runs-on` change,
     which is Software's routing (DS-8237, code-review Y-8).
