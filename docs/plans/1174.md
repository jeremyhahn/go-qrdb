# Plan: #1174 — public verbs read one table on every transport

## Objective

An operation's login requirement is the same on REST, gRPC, Unix, QUIC and
MCP (rulings 158, 264(b)). Health and invitation-redeem need no login
anywhere, are read from one table (`pkg/api/publicverbs.Table`), and draw
their rate-limit bucket by caller address before serving.

## Slices

1. **Part 1 (#1550, merged):** the `publicverbs.Table`; every transport's
   auth chain and the buildgates public-surface scan read it; proto Health
   moves to `identity:public`; per-transport rate limit on public Health.
   Tests: `publicverbs` unit tests, per-transport public rate-limit tests,
   MCP no-login health tool tests.
2. **Part 2 (separate lane):** cross-transport parity tests that the table
   and each transport's chain agree.
3. **Part 3 (#1553):** the Go SDK `Connect` succeeds with no credential
   against public Health; one MCP refusal capture for `initialize` and
   `tools/call`; REST 401 reads unauthenticated. CLI E2E: `qrdb admin
   health` with no credential on every transport (multi-protocol harness).
   Docs and CHANGELOG: Health public everywhere, `admin:health` only as a
   rate-limit dimension; soak role example drops `admin:health`.

## Out of scope

- Removing the `admin:health` permission from built-in roles' catalogue
  (it stays as the rate-limit dimension name).
- New public verbs beyond health and invitation-redeem.
