Results:

- Round 3 P1 2 closed: slice 1 (the fence), slice 2 (the resync).
- Round 2 P1 4 closed by slice 3. A ReadIndex probe that is not yet served,
  or that ran out its own 500 ms timeout, is "not yet"; `ErrShardNotFound`,
  `ErrClosed` and any other probe error fail the reopen. Each replica's wait
  is bounded by `CatchUpTimeout` (default 2 min, `ErrMoveCatchUpTimeout`).

  they cannot back out further.

  tenant's placement keys in its transaction. Placements live in

  key encoding. The window is closed instead by the fence (no rebalance MOVE
  or scale-up of a moving tenant), the scheduler filter (no new replica),
  and the resync immediately before cut over. A replica change made outside
  all three between that resync and the cut-over transaction is not
  caught.

## rw925g

### Defect (Codex round 3 P1 4)

`cmd/qrdbd/start.go` started the tenant move worker as a bare
`go moveWorker.Run(bootCtx)` (after `server.WireTenantMoves`, near :2645)
with no handle. The `case <-sigCtx.Done():` branch then closed the dedicated
raft shards, the per-tenant volume hosts and every per-tenant Pebble
(`perTenantReg.CloseAll`), stopped the server and shut the node down while a
`TenantMoveWorker.Tick` (`pkg/server/move_wiring.go:215`) could still be in
`RunLocalSteps`, a settle or a reopen retry: a step that closes, copies and
reopens tenant stores and writes the journal. The `case req := <-migrateCh:`
branch had the same gap: `handleSystemMigration` stopped `svcNode` and the
next boot iteration started a second worker while the first tick could still
run. The embedded node (`sdk/go/node/node.go` `startTenantMoves` and
`stopTenantMoveWorker`) already cancelled and waited.

### Fix

- `pkg/server/move_worker_start.go`: `TenantMoveWorker.Start(ctx) (stop
  func())` runs `Run` in a goroutine; `stop` cancels it and blocks until `Run`
  has returned, is idempotent and safe from several goroutines.
- `cmd/qrdbd/start.go`: `Start` replaces the bare goroutine; `stopMoveWorker`
  lives at the boot-iteration scope and is called first in the signal branch,
  first in the migration branch, before `shutdownNode` on every error return
  after the worker starts, and by a `defer` for the rest. A step cut short by
  the cancel resumes from the journal and the reopen retry at the next boot,
  so the fix is ordering only.

  `TestTenantMoveWorker_StopWaitsForInFlightTick` (stop does not return while
  a step is blocked, returns once it does), `TestTenantMoveWorker_StopIdempotent`

  `TestTenantMoveWorker_StopAfterParentCancel`.
- `test/integration/volume_move_shutdown_cli_test.go`:

## rw925h

Codex round 4, P1 1 on PR #1677: a resumed move step settles without catching
up its replicas.

**Defect.** After a restart with `StepSettling` set, `MoveReconciler.runStep`
calls `SettleMoveStep`, which calls `OpenTenantStores` on a fresh
`MoveStoreCloser` that never ran `CloseTenantStores`. With no close record,
`reopen` attached no shard and waited for no catch-up, so the step was
released while the clustered boot left the tenant's shards to the
asynchronous shard reconciler: the leader could grant the next node's step
before this replica had started, losing the one-replica-at-a-time quorum
guarantee. A copy step re-run after a restart had the same root cause:
`CloseTenantStores` listed only the started shards, so a replica the shard
reconciler had not started yet was neither recorded nor caught up.

**Fix.** `MoveStoreCloser` takes the tenant's local replicas from durable
placement (`MoveLocalReplicas`, `WithMoveLocalReplicas`). `localMoveReplicas`
(pkg/server/move_wiring.go) returns the databases whose placement replicas
include this node's system-shard raft address; `newMoveStores` wires it.
`CloseTenantStores` records every placed replica, closing only the started
ones; a lookup error fails the close. `reopen` of a tenant with no close
record takes its databases from placement; a lookup error leaves the tenant
pending for `RetryReopen`. An `Attach` that fails while the shard reconciler
has started the shard counts as started. Every database waits in
`awaitCaughtUp`. An IsolationVolume tenant has one replica and no placement:
its Host path is unchanged.

**Tests.** `TestMoveStoreCloser_ResumedSettleReopensPlacedReplicas`,
`TestMoveStoreCloser_ResumedSettleLookupFailureStaysPending`,
`TestMoveStoreCloser_CloseRecordsUnstartedPlacedReplica`,
`TestMoveStoreCloser_CloseLookupFailureFailsClose`,
`TestMoveStoreCloser_AttachRaceWithReconcilerCountsStarted`,
`TestLocalMoveReplicas` (pkg/server) and
`TestMoveReconciler_ResumedSettleDoesNotReleaseUntilSettled` (pkg/volume).
`TestVolumePool_CLI_MoveTenant` and
`TestVolumePool_CLI_MoveTenant_ShutdownDuringMove` rerun unchanged on every
transport. The three-node restart-during-settle case is
`TestVolumePool_CLI_MoveTenant_ThreeNode_RestartWhileSettling` (rw925k).
