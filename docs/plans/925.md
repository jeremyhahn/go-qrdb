# Plan: #925 volume-pool tenant moves

Objective: move a tenant's closed replica directory from its source pool
mount to its destination pool mount, node by node, behind a move journal
`__sys:volumepool/moves/{tenant}`, cut over by one assignment write
(docs/decisions/volume-pool-tenant-moves.md; Q1-Q8 and Q10 adopted, ruling
1115; Q9 decided by the owner, owner queue 287: C, refused outright).

Multi-node (rw925a, not built; blocker): the three-node stop/reopen/catch-up
move E2E cannot be written as briefed. A `volume`-isolation tenant is a
single-node Host (`pkg/server/tenant_host.go`; the move's replica-node
source moves a tenant with no placement on its own node only,
`pkg/server/move_wiring.go`), so it has no replica on another node to stop,
restart and catch up, and "every value reads back from every node" does not
apply to it. The case needs a `raft`-isolation tenant placed on all three
nodes, and the cluster fixture (`startMultiProtocolCluster`) needs: a
per-node config (each node its own `default`/`second` pool paths; today one
shared `writeMultiProtocolSealConfig` file), the raft-tenant entitlements
and quotas of `volumeMoveYAML`, and `bin`/`startArgs` kept on each node so
`multiProtoNode.restart` can stop and restart one. The stop is
deterministic without sleeps: stop a replica right after `move-tenant`
returns; the move cannot complete until that node runs its own copy step
after its restart. Owner/coordinator question: confirm the case runs on a
`raft`-isolation tenant, then a next slice builds it (test/integration only).
The runtime half of the gap, a stranded tenant after a failed reopen, is
closed by the reopen retry above.
## PR #1677 Codex round 1 (head 2b0569718d, rw925b)

Four P1s, one commit each:

1. Delete vs admit race. `Catalog.FenceForDelete` CAS-writes
   `Assignment.Retiring` in the same compare that proves no move journal
   exists; `AdmitMove` refuses a retiring assignment and compares the
   assignment's raw value, so a fence and an admit cannot both win.
   `deleteTenant` calls the fence (seam `moveFencer`) before any tombstone.
   Tests: `catalog_move_test.go` (fence then admit, admit then fence,
   idempotent fence), `pkg/tenant` (a delete racing an admit never destroys
   a tenant with a journal).
2. Settling copy step. `RecordMoveStep` records the copy but keeps
   `StepNode` with `StepSettling`; `ReleaseMoveStep` releases the step only
   after `SettleMoveStep` reopened and caught up (`CompleteMoveStep` is
   record and release in one transaction, for a runner with no settle). A failed settle is re-settled on
   the next pass; no grant, abort grant or cut over while a step settles.
   Tests: `move_journal_test.go`, `move_reconciler_test.go`.
3. Abort cleanup retention. `RecordAbortStep` holds the step settling
   (`StepCopied` for a copied node); the journal and the ToPool reservation
   stay until the last node's `ReleaseMoveStep`, after the destination was
   removed. Boot removes a settling
   aborting node's destination. Tests: `move_journal_test.go`, `pkg/seal`.
4. Three-node raft-tenant move E2E (see "Multi-node").

P1 2 and 3 fixed: merge b7c5dff24 reconciles the head's 64785d986e/0b06fb559c with the base's 9e0d884f75/ad280f9f25 (one fence: `FenceForDelete`, never lifted; one settle machine: Record/Release), and b785f9430 tests the settle failure paths.

## PR #1677 Codex round 2 P1 1 and 2 (rw925d)

- P1 1, non-idempotent reopen: a settle pass whose `ReleaseMoveStep`
  failed after `OpenTenantStores` succeeded, or a boot that restored a
  tenant whose journal still records the step settling, called
  `BarrierRegistry.ReopenVolumeTenant` on a barrier already registered;
  `RegisterTenant` refused it with `ErrTenantAlreadyExists` on every later
  settle. `ReopenVolumeTenant` now reuses a barrier registered at the data
  root `RequireInsideLocalPool` resolves now (the registry records each
  volume tenant barrier's root, `VolumeTenantDataRoot`), still ends the
  hold, unseals an auto-unseal tenant left sealed and leaves an unsealed
  one as is; a barrier registered at another root fails closed with
  `*VolumeTenantRootMismatchError`. Tests (`pkg/seal/move_runner_test.go`):
  `TestReopenVolumeTenant_TwiceAutoUnseal`,
  `TestReopenVolumeTenant_TwiceSelfManagedStaysSealed`,
  `TestReopenVolumeTenant_AfterRestoreVolumeTenants`,
  `TestReopenVolumeTenant_RefusesBarrierOnOtherPool`.
- P1 2, torn `ResolveForNode`: a cut-over, or the retire that deletes the
  journal, between the assignment read and the journal read returned the
  stale source assignment. `Catalog.ResolveForNode` re-reads the
  assignment after the journal and retries the pair until both reads agree
  (pool and raw record), at most 8 attempts, then
  `*ResolveInconsistentError`. Tests
  (`pkg/volume/move_resolve_consistency_test.go`): a cut-over and a
  cut-over plus journal delete injected between the reads both resolve to
  the destination; a record rewritten on every pass ends in the typed
  error after 8 attempts.

## PR #1677 Codex round 2 P1 3-4 and round 3 P1 2 (rw925e)

Objective: every replica of a moving tenant is moved, and a stalled settle
catch-up neither blocks other tenants nor retries forever. Slices, in order:

1. Fence (round 3 P1 2, first half). One refusal type,
   `volume.TenantMovingReplicaError` (FailedPrecondition), replaces the
   lifecycle copy. A `service.MoveFence` seam is consulted by
   `RebalanceService.moveTenantGroupShard` before the observer add and the
   source removal, and by `DatabaseService.scaleUp` before each add; it is
   wired in lifecycle over the same `volume.Service` as the scheduler filter.
   Tests: rebalance MOVE and scale-up of a moving tenant refused before any
   placement write or membership change; filter uses the shared type.
2. Resync (round 3 P1 2, second half). `volume.MoveNodeSource` on the
   `MoveReconciler` (`WithMoveNodeSource`, wired from
   `moveReplicaNodeSource`); `ReconcileOnce` resyncs before each grant and
   before cut over through `Catalog.SyncMoveNodes` (adds unseen nodes as
   pending, a copied move goes back to copying, drops a departed pending
   unstepped node); no cut over in a pass whose resync changed the journal.
   Tests: `move_journal_test.go`, `move_reconciler_test.go`.
3. Bounded settle (round 2 P1 4). `TenantMoveConfig.CatchUpTimeout`
   bounds `awaitCaughtUp`; `readIndexCaughtUp` returns a permanent
   shard failure as an error; a failed settle is recorded
   (`Catalog.FailSettleStep`, sanitized error, attempts) and past the
   attempt bound a copy-phase settle aborts like a cancel after copy; a
   cancel is honoured at the next settle attempt. Tests: `move_wiring_test.go`,
   `move_store_closer_test.go`, `move_journal_test.go`,
   `move_reconciler_test.go`.
4. Docs: engineering.md invariants and concurrency, CHANGELOG.

Out of scope: the three-node raft-tenant move E2E (round 3 P1 3, see
"Multi-node") and round 3 P1 4 (review capacity).
