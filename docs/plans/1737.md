# #1737 TransactionalDAO Commit and BatchSave: one atomic guarded batch

## Objective

`daoTransaction.Commit` claims to apply its queued operations atomically but
called `Save`/`Delete` one at a time, and `SaveWithCondition` read, evaluated
and then wrote with no guard. `BatchSave` and `WithTx` inherit the defect.
Commit now builds ONE `PutAllIfAllUnchanged` batch on a
`kvstore.MultiGuardedBatchKVStore`, the path `UnitOfWork.Commit` already uses:

- a save is a put; a save whose ID came from a `DeterministicIDGenerator`
  carries the same create/update/collision guard UnitOfWork uses;
- a delete is a delete;
- a `SaveWithCondition` is a put guarded on the exact bytes (or absence) the
  condition was evaluated against, so a concurrent change between evaluation
  and commit refuses the whole batch;
- every condition is evaluated before anything is written; any refusal
  leaves the store unchanged.

No sequential fallback and no compat path (rulings 1354/1355): a store
without the batch interface gets `*AtomicBatchUnsupportedError`, as
UnitOfWork does. Mode-neutral, tested standalone and raft (ruling 1350).

## Slice 1 (pkg/dao)

- Shared helper in `unit_of_work.go`: the guarded-batch commit (guards from
  deterministic saves plus caller guards, refusal mapped to
  `IDCollisionError` / `kvstore.ErrNotApplied`) and the save ID assignment.
- `transaction.go` Commit routes through it; the per-op loop is removed.
- Tests (`transactional_dao_test.go`):
  1. a commit whose 3rd op fails leaves the first two unapplied;
  2. a `SaveWithCondition` whose record changes after evaluation refuses
     the whole batch;
  3. a store without `MultiGuardedBatchKVStore` gets
     `AtomicBatchUnsupportedError`.
- Existing transactional tests move to a guarded memory store.

## Slice 2 (sdk/go conformance + docs)

- The same three cases over `sdk.NewEmbeddedKVStore` (standalone pebble)
  and the raft-backed conformance store.
- Docs: Commit/BatchSave/WithTx are all-or-nothing; name the refusals.

## Out of scope

docs/SPEC.md, ROADMAP.md, go.mod, new public API beyond the fix.
