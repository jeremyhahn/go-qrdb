# #1744: cloud backup recovery tests prove recovery

## Objective

The raft cloud backup round trip (Azure, GCS, S3 stubs) restored the backup
onto the intact shard that made it. That restore is a no-op
(logdb.ErrSnapshotOutOfDate is treated as success), so the test passed without
installing any backup data. The test must restore onto a replacement shard
with the same identity and no local state, and prove the keys come from the
backup.

## Slice 1 (sdk/go/node/backup_destination_cloud_test.go)

- Back up the dedicated raft shard of acme/orders on `first`; keep the
  objects() and VerifyBackup checks.
- Put a sentinel key after the backup (not in the backup), then close `first`.
- Start a replacement node (fresh data and pool dirs, same stub destination),
  create the same pool, tenant and database; require the same shard ID.
- Before the restore: every backed-up key and the sentinel are absent.
- ListBackups/VerifyBackup on the replacement, then RestoreBackup onto the
  shard: no error, no Errors, ShardsRestored == 1.
- After the restore: all 20 keys hold their values, the sentinel is still
  absent, and the shard accepts a new write.

Tests: TestBackupDestination_{Azure,GCS,S3}_RaftNodeRoundTrip
(`make test-objstore-cloud`).

## Out of scope

- Production code, unless the test proves a real bug.
- The other cloud tests, standalone restore (online backup is unsupported on
  LocalBackend), the offline restore path.
