# Plan: standalone and non-Raft writes fsync before acknowledging (#1617)

## Objective

A standalone node acknowledges writes that are not durable. The data-plane
Pebble store is opened with `pebble.DefaultConfig`, which sets
`SyncWrites: false` on the premise that "Raft WAL provides durability", so
every write goes through `pebble.NoSync`. A standalone node has no Raft WAL:
an acknowledged Put can be lost on SIGKILL or power loss. Make the Pebble
store durable by default.

## Slices (in order)

1. Test first: `sdk/go/node/node_sigkill_test.go` asserts that every key
   acknowledged before the SIGKILL ("alpha" plus a few Puts acknowledged
   just before the kill) reads back after the restart. Fails on the base.
2. `pkg/storage/pebble/config.go`: `DefaultConfig` sets `SyncWrites: true`;
   the doc comment says durable by default, and that a store may turn
   SyncWrites off only when another log already fsyncs the write before it
   is acknowledged. Unit test: `DefaultConfig(dir).SyncWrites` is true.
3. Review the other `DefaultConfig` callers (lifecycle/local.go,
   database/factory.go, sdk standalone/storage/timeseries, cmd/qrdb
   bindings_server.go and embedded_barrier.go, sdk/go/node/node.go): none
   may set SyncWrites false.
4. Docs: any page under docs/ stating the NoSync default is updated;
   CHANGELOG.md entry under Fixed.

## Out of scope

- `pkg/statemachine/registry.go` (disk/fast state machines): issue #1618.
- Performance tuning of sync batching (WALMinSyncInterval etc.).
