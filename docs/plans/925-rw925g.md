### Defect (Codex round 3 P1 4)

`cmd/qrdbd/start.go` started the tenant move worker as a bare
`go moveWorker.Run(bootCtx)` (after `server.WireTenantMoves`, near :2645)
with no handle. The `case <-sigCtx.Done():` branch then closed the dedicated
raft shards, the per-tenant volume hosts and every per-tenant Pebble
(`perTenantReg.CloseAll`), stopped the server and shut the node down while a
`TenantMoveWorker.Tick` (`pkg/server/move_wiring.go:215`) could still be in
`RunLocalSteps`, a settle or a reopen retry: a step that closes, copies and
reopens tenant stores and writes the journal. The `case req := <-migrateCh:`
branch had the same gap: `handleSystemMigration` stopped `svcNode` and the
next boot iteration started a second worker while the first tick could still
run. The embedded node (`sdk/go/node/node.go` `startTenantMoves` and
`stopTenantMoveWorker`) already cancelled and waited.

### Fix

- `pkg/server/move_worker_start.go`: `TenantMoveWorker.Start(ctx) (stop
  func())` runs `Run` in a goroutine; `stop` cancels it and blocks until `Run`
  has returned, is idempotent and safe from several goroutines.
- `cmd/qrdbd/start.go`: `Start` replaces the bare goroutine; `stopMoveWorker`
  lives at the boot-iteration scope and is called first in the signal branch,
  first in the migration branch, before `shutdownNode` on every error return
  after the worker starts, and by a `defer` for the rest. A step cut short by
  the cancel resumes from the journal and the reopen retry at the next boot,
  so the fix is ordering only.
