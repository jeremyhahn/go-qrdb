## rw1708w1: Codex P1 and Lint Gates on #1709

### (1) Codex P1: the Row gate unioned the live labels with the event's

- Defect: the Row job's inline python (`.github/workflows/ci.yml`, "Row
  check") added the labels read live from the API to `EVENT_LABELS`
  (`labels |= ...`), so an exempt label (for example `ci`) removed after the
  event still exempted a rerun.
- Fix: a successful live read is the label set alone; the event's labels
  are used only when there is no URL/token or the read fails (the existing
  `::warning::` fallback).
- Regression: `.github/workflows/testdata/row-job-tests.py` R13 serves the
  live labels from a loopback HTTP server: the event has `ci`, the live read
  has only `bug`, the head branch is `fix/lint`; want red with no warning.
- Commands: `python3 -I .github/workflows/testdata/row-job-tests.py` (the
  ci.yml "Row job tests" step). Before the fix: R13 FAIL (rc 0), 1 FAILED.
  After: ALL PASS.

### (2) Lint Gates: the composer test could not create its Go build cache

- Defect: `TestSDK_ExternalComposerReachesEverySeam` (make
  check-action-pins) failed with `mkdir /cache/gobuild/00: no such file or
  directory`. The inner `go test` inherits `GOCACHE=/cache/gobuild`, the
  bind mount of `<gen>/gobuild`.
- Cause: `scripts/ci-cache-dir.sh` created the generation directory but not
  its `gobuild` and `golangci` subdirectories; with the folded fallback root
  (`$RUNNER_TEMP/ci-cache` when `CI_CACHE_ROOT` is unset) nothing else
  guaranteed them before the stage ran.
- Fix: `select_locked` makes `<gen>/gobuild` and `<gen>/golangci` (mkdir -p)
  for the generation it selects, under the lock, whatever the root.
- Regression: `scripts/ci-cache-dir_test.sh`: with `CI_CACHE_ROOT` unset and
  `RUNNER_TEMP` set, the emitted dir has writable `gobuild` and `golangci`.
  The fake-du case now counts both subdirectories (18 GB, not 9).
- Commands: `bash scripts/ci-cache-dir_test.sh`. Before the fix: the new
  check FAIL. After: ok. `bash -n` on both scripts: clean.
- Open: pool runners are containers sharing only the Docker daemon
  (scripts/ci-image.sh lock_file note), so a `$RUNNER_TEMP` path may not
  exist on the daemon's host; if Lint Gates stays red after this, the
  fallback with `CI_CACHE_ROOT` unset should be the named volumes instead.
