# #566 sleep sweep 10 (rw566o)

Sweeps 2-9 grepped only `time.Sleep`. The same sleep written as a bare
`<-time.After(d)` statement (a receive whose value is discarded, standing alone
on its line) was never swept; at the sweep's base `git grep -nE
'^\s*<-time\.After\(' -- '*.go'` found 12 sites, all in `pkg/discovery` tests.
A `<-time.After` inside a `select` (a timeout arm) is not a sleep and is out of
scope. Line numbers below are the lines before the sweep. Each sleep stood in
for synchronisation (ruling 273(12)) and becomes one of three forms, in order
of preference:

- (a) a wait on state the test already owns (peer count, `Written()`, a call
  or read counter the fake bumps) with `require.Eventually` or the package's
  `waitForPeerCount` / `waitForWritten`, or by running the blocking call in a
  goroutine while the test goroutine waits on the observable state;
- (b) where the elapsed time itself is under test (timestamps, the replay
  window, an absence window after Stop), the test body runs in
  `synctest.Test`, so the wait is a fake-clock advance: a `time.Sleep` inside
  the bubble, the kept form already recorded for
  `pkg/volume/reporter_seal_test.go:169`, or `synctest.Wait()`;
- (c) a helper with no `*testing.T` keeps a ticker wait (`poll :=
  time.NewTicker(d); defer poll.Stop()` before the loop, `<-poll.C` in the
  sleep's place).

No production code changes, and no behaviour loses its test: every rewritten
wait is exercised by the test that contains it, and the fake transport's read
by every multicast test.
