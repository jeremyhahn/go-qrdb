# Plan: #1651 IAM exposure

## iam1651b: tenant-status list filter

**Decision.** The tenant list takes an optional status filter on every
surface: REST (`?status=`), gRPC and Unix (`TenantListRequest.status`,
replacing `google.protobuf.Empty`), QUIC (`tenant.List` payload), MCP
(`qrdb_tenant_list` `status`), embedded, the Go SDK
(`TenantClient.ListTenants(ctx, *transport.ListTenantsRequest)`, nil lists
all) and the CLI (`qrdb tenant list --status`).

**Semantics.** `tenant.FilterByStatus` holds the rule. Empty is no filter.
`active`, `suspended` or `disabled` keeps only tenants stored with exactly
that status, so a legacy tenant with no stored status matches only the
unfiltered list. Any other value is refused with `*tenant.InvalidStatusError`
naming the allowed statuses (400 / `INVALID_ARGUMENT`).

**Where it runs.** At the API surfaces, after `FilterTenantList`, so the
filter can only narrow what the caller may already see.
`TenantServicer.ListTenants` stays unfiltered for internal callers.

**`deleted` is not a status.** A deleted tenant is a retired-id tombstone,
listed by `ListDeletedTenants` / `qrdb tenant list-deleted`; `--status
deleted` is refused as an invalid status rather than mapped to that list.

**Tests.** `pkg/tenant` `TestFilterByStatus_*`; per-server
`StatusFilter` tests on gRPC, QUIC, REST and MCP; SDK embedded
`TestListTenants_StatusFilter`, REST `TestListTenants_SendsStatusQuery`, MCP
`TestListTenants_SendsStatusArg`; `cmd/qrdb` `TestTenantList_StatusFlagIsSent`;
CLI E2E `TestTenantStatus_CLI_ListStatusFilter_PerProtocol` over REST, gRPC,
QUIC, MCP and Unix.
