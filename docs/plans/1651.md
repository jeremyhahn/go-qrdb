## iam1651b: tenant-status list filter

**Decision.** The tenant list takes an optional status filter on every
surface: REST (`?status=`), gRPC and Unix (`TenantListRequest.status`,
replacing `google.protobuf.Empty`), QUIC (`tenant.List` payload), MCP
(`qrdb_tenant_list` `status`), embedded, the Go SDK
(`TenantClient.ListTenants(ctx, *transport.ListTenantsRequest)`, nil lists
all) and the CLI (`qrdb tenant list --status`).

**Semantics.** `tenant.FilterByStatus` holds the rule. Empty is no filter.
`active`, `suspended` or `disabled` keeps only tenants stored with exactly
that status, so a legacy tenant with no stored status matches only the
unfiltered list. Any other value is refused with `*tenant.InvalidStatusError`
naming the allowed statuses (400 / `INVALID_ARGUMENT`).

**Where it runs.** At the API surfaces, after `FilterTenantList`, so the
filter can only narrow what the caller may already see.
`TenantServicer.ListTenants` stays unfiltered for internal callers.

**`deleted` is not a status.** A deleted tenant is a retired-id tombstone,
listed by `ListDeletedTenants` / `qrdb tenant list-deleted`; `--status
deleted` is refused as an invalid status rather than mapped to that list.

**Tests.** `pkg/tenant` `TestFilterByStatus_*`; per-server
`StatusFilter` tests on gRPC, QUIC, REST and MCP; SDK embedded
`TestListTenants_StatusFilter`, REST `TestListTenants_SendsStatusQuery`, MCP
`TestListTenants_SendsStatusArg`; `cmd/qrdb` `TestTenantList_StatusFlagIsSent`;
CLI E2E `TestTenantStatus_CLI_ListStatusFilter_PerProtocol` over REST, gRPC,
QUIC, MCP and Unix.

## iam1651c: Unix peer-credential identity

**Decision.** On Linux the Unix listener reads `SO_PEERCRED` (uid, gid, pid)
from each accepted connection before the TLS handshake, and the gRPC
interceptors bind it into the request context (`auth.WithPeerCredential`).
`unix.peer_credentials` maps a uid, or a primary gid, to a tenant and
username; `auth.PeerCredentialAuthenticator` (method `peercred`) is installed
last in the authentication chain only when a mapping exists.

**Semantics.** A mapping names an account, never a role: the identity is
filled from the stored account and its roles decide through RBAC. A missing
account holds no roles, so every request is denied. An account's
`auth_methods`, when set, must list `peercred`. A uid match wins over a gid
match. An unmapped peer is refused with `peer_credential_unmapped`
(`UNAUTHENTICATED`). A client certificate or consumer authenticator on the
socket decides first. Config validation refuses a mapping with both or
neither of uid and gid, an empty user, and a duplicate uid or gid, even
while `protocols.unix` is off.

**Tests.** `pkg/auth` and `pkg/api/unix` `PeerCred` tests; the wiring and
middleware chain-order tests; `pkg/config` `TestUnixPeerCredentials_*`; CLI
E2E `TestUnixPeerCredential_CLI_BindsMappedUser` (a certificate-less caller
is refused, then admitted once its mapped account holds `operator`, and
still refused `users create`).

**Open owner question.** Should a gid mapping also match the peer's
supplementary groups? `SO_PEERCRED` reports only the primary gid, so today a
gid mapping matches the primary group only; supplementary groups would need
a `/proc/<pid>/status` read, which races a pid reuse. Recommendation: keep
primary gid only. A second question: should a mapping to a system-tenant
account (empty `tenant`) be refused at validation? Recommendation: allow it,
since the account's roles still bound it, but say so in the docs.

## iam1651d

SPEC item (2) authz-claim-roles: an identity's roles come only from the
go-qrdb user record it binds to.

- Change: `finalizeIdentity` (`pkg/auth/middleware/middleware.go`) now clears
  `Roles` up front, beside `RoleBindings` and `Attributes`, so no path keeps
  the roles an authenticator returned. Only a found, active record's
  `RoleIDs` set them. The `Identity.Roles` and `Authenticator` docs in
  `pkg/auth/auth.go` say so.
- Paths closed, all through the one `authenticate()` call every transport
  (REST, gRPC, Unix, QUIC, MCP) shares:
  - Subject with no user record: it used to keep its claimed roles; now it has
    none, so RBAC default-denies it.
  - Node with no user store: same.
  - Sealed tenant: claimed roles were kept; now only the IdentityGated
    surface stays reachable.
  - A capability module's fallback identity (for example a token go-xkms
    minted) claiming Admin: refused unless go-qrdb holds a record granting it.
  - Holder identities were already cleared; the separate clear in that
    branch is gone, because the up-front clear covers it.
- Test fixture: `authtest.FixedAuthenticator.Users()` (`fixed_users.go`) is a
  read-only store holding the record of the identity the authenticator
  currently returns. Every test that relied on a fixed caller's roles now
  pairs `authmw.WithAuthenticator(fa)` with `authmw.WithUserService(fa.Users())`.
  Migrated: 22 test files in `pkg/api` and the SDK (5 `grpctest` helpers,
  which also drive `pkg/api/unix`; `grpc/service_vlog_test.go`; 5 in mcp, 5 in
  quic, 5 in rest; `sdk/go/transport/internal/sotest/sotest.go`) plus 4
  middleware test files. Callers whose tests do not depend on the caller's
  roles (allow-all or deny-all authorizers, `pkg/server`, and the rest files
  `encoded_path_authz`, `handlers_audit_verify_scope`,
  `handlers_delegation_policy`, `module_route_guard`, `role_assignment_wiring`
  and `certs_tenant_scope`) were left alone; their packages pass unchanged.
- Tests: `pkg/auth/middleware/claim_roles_test.go` covers all four
  finalizeIdentity paths, the REST fallback against the real RBAC PDP (403 →
  200 only with a record) and the gRPC/Unix interceptor (PermissionDenied → OK
  only with a record). `pkg/auth/authtest/authtest_test.go` covers the
  fixture store.
- No CLI e2e: a CLI user always authenticates against a node whose user store
  holds their record, so what the CLI sees does not change. The closed paths
  need an authenticator that returns roles (a capability module's fallback or
  a test double), which the CLI cannot inject. The unit tests drive the shared
  `authenticate()` path and both interceptors with the real PDP.
- Not run here: `pkg/sql/mysql` and `pkg/sql/pgsql` build only under the
  `qrdb_mysql` / `qrdb_pgsql` tags, and their driver modules are not in the
  lane's offline module cache (GOPROXY=off). Neither package is edited; CI
  runs them.

Open question for the owner (not implemented):

- `RBACClient.Authorize` / `POST /permissions/authorize` still evaluates the
  `Roles` the caller sends in the wire `Identity`. That is the same claim
  path, one hop out: a client can ask "would these roles allow X" and the
  PDP answers from roles no record grants. Recommendation: resolve the
  subject's roles on the server from its bound user record (the same
  `finalizeIdentity` binding), and drop `Roles` from the wire `Identity`
  outright, with no compat field. A "what-if" evaluation over named roles,
  if it is wanted, would be a separate admin-only call that says so.

## iam1651e

SPEC item (5) authz-object-owner: an object-owner ABAC condition beside the
tenant check `OwnTenant`, so go-xkms drops its own owner check.

- Go rule: `pkg/auth/object_owner.go` (`WithResourceOwner`,
  `ResourceOwnerFromContext`, `OwnObject`, `ObjectOwnerDeniedError`).
- ABAC: `pkg/auth/abac/types.go` (`ResourceOwnerContextKey`),
  `decorator.go` (owner into the check request), `parser.go`
  (`subject.owns_resource`, `ownsResource`).
- SDK: `sdk/go/types_object_owner.go` (`sdk.OwnObject`,
  `sdk.WithResourceOwner`, `sdk.ResourceOwnerFromContext`,
  `sdk.ObjectOwnerDeniedError`, `sdk.ABACResourceOwnerContextKey`).
- Tests: `pkg/auth/object_owner_test.go`,
  `pkg/auth/abac/parser_test.go` `TestConditionParser_OwnsResource`,
  `pkg/auth/abac/object_owner_test.go`, `sdk/go/types_object_owner_test.go`,
  CLI e2e `TestABACPolicy_CLI_ObjectOwnerCondition_PerProtocol`.
- Docs: `docs/identity-rbac/engineering.md`, `user.md`, `cli.md`,
  `CHANGELOG.md`.

Convention decisions:

- The condition is a built-in boolean subject field `subject.owns_resource`,
  beside `subject.authenticated` and `subject.mfa_verified`: true only when
  the request carries a non-empty resource owner equal to a non-empty subject
  id, false otherwise (fail closed when the owner is absent or the subject id
  is empty). `compareEqual` is unchanged; a hand-written
  `resource.owner == subject.id` is not a safe owner test.
- The owner is carried server-side through the context, the way the target
  tenant is: `auth.WithResourceOwner(ctx, ownerID)`, set by the embedder's
  store before it asks the PDP, never from a caller-written request field.
- The Go rule is `auth.OwnObject(ctx, owner, op string) error`, OwnTenant's
  shape, in `pkg/auth` because it needs the identity, which `pkg/tenant`
  cannot import. Its refusal unwraps to `auth.ErrUnauthorized`
  (PermissionDenied) with no errclass edit.
- No wire field is added: go-qrdb has no owner-bearing object on its
  transports; the over-the-wire surface is the stored policy that uses the
  condition.
