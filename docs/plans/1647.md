# Plan: #1647 SealStoreClient on every transport (docs/18 V12, SealStore half)

#1660 shipped the PermissionClient half. This row ships the SealStore half.

## Objective

`transport.SealStoreClient` answers on all six transports (embedded, grpc,
rest, quic, unix, mcp) instead of embedded only, gated server-side by
`permission.SealStoreManage` (`seal:store_manage`, ScopeCross, SO-exclusive),
the same permission the embedded transport checks.

## Slices

1. Shared remote client: `transport.SealStoreEndpoints` +
   `NewRemoteSealStoreClient` (`sdk/go/transport/seal_store_remote.go`),
   mirroring `permission_remote.go`. Refuses nil requests and empty names
   before the wire. Test: `seal_store_remote_test.go` (round trip, refusal
   without a wire call).
2. Server endpoints, one per listener, each gated by `seal:store_manage`:
   gRPC RPCs in `qrdb.proto` (regenerated), REST `/v1/seal-store/...`, QUIC
   `sealstore.*` methods, MCP `qrdb_seal_store_*` tools; the server holds a
   `*seal.SealStore` over the node barrier.
3. Client wiring on grpc, rest, quic, unix and mcp with
   `var _ transport.SealStoreClient` assertions.
4. E2E on each of the six transports (no sleeps); docs: SPEC.md SDK row,
   `sdk/go/doc.go`, identity-rbac and barrier-seal engineering docs (the
   "no network route" statements change).
5. CLI: `qrdb seal-store` verbs, CLI E2E on every network transport and an
   embedded CLI test (fs1647a).
6. Refusal E2E: a tenant identity without `seal:store_manage` is refused every
   seal store call with the transport's typed permission denial over the SDK
   and the CLI on every network transport; CHANGELOG entry; stale "gRPC and
   unix" comments corrected (dr1647q). The QUIC seal store and permissions
   clients return the `t.call` error as-is, so a refused call keeps its wire
   status (dr1647r).
7. Lane-verify Codex security P1s closed (fr1647n, fr1647o, fr1647p): secret
   guard (https only, no redirect) on REST/MCP put and get; the seal store
   migrated by `recodeSystemBarrier` on `enable-encryption`; atomic,
   serialized reseal; the secret-name rule on the server
   (`seal.ErrInvalidSecretName`) and in the SDK before the wire
   (`transport.ErrSealStoreInvalidName`). Tests: `pkg/seal/seal_store_test.go`,
   `TestRemoteSealStoreClient_RefusesInvalidNamesBeforeTheWire`,
   `TestRemoteSealStoreClient_AcceptsOpaqueNames`.
8. `seal.ErrInvalidSecretName` is classed InvalidArgument in
   `pkg/api/errclass/table.go`, so every transport answers invalid-argument
   (REST 400, gRPC/Unix InvalidArgument, QUIC `StatusInvalidArgument`, MCP the
   invalid-argument tool code); REST's local special case is deleted (fr1647q).
   Tests: `TestGRPC_SealStore_InvalidNameIsInvalidArgument`,
   `TestUnix_SealStore_InvalidNameIsInvalidArgument`,
   `TestSealStoreOverQUIC_Errors/invalid name`,
   `TestSealStoreTools_InvalidNameIsInvalidArgument`.

## Codex verify at 24de2ee0b0

- P1 crash after the commit point: `recodeSystemBarrier`
  (`cmd/qrdbd/system_migrate.go`) names the seal-store keyspace in
  `MigrationJournal.StagedRecords` before it stages, and stages, verifies,
  rolls back and commits through `pkg/seal/migrate_records.go`; a commit
  failure keeps the committed journal, so boot's `RecoverInterruptedMigration`
  rolls the records forward. The bespoke helpers are deleted (fr1647r).
  Tests: `TestRecodeSystemBarrier_SealStoreCrashAfterCommitRollsForwardAtBoot`,
  `TestRecodeSystemBarrier_SealStoreCommitFailureKeepsJournal`.
- P1 TLS: gRPC, Unix and QUIC `PutSealStoreSecret`/`GetSealStoreSecret`
  call `requireTLS(transport.SealStoreSecret(true))` before the wire.
  Tests: `TestSealStoreSecret_RequiresTLS` (grpc, unix),
  `TestSealStoreSecret_HTTPAddressIsRefused` (quic).
- P1 plaintext history: `sealStoreCompactor` (`cmd/qrdbd/seal_subsystem.go`)
  flushes and compacts the seal Pebble store after the commit and before the
  journal is cleared; boot compacts again after rolling a committed
  seal-store journal forward. Test:
  `TestRecodeSystemBarrier_SealStoreRetiresPlaintextHistory` (disk-backed).

## lane-verify Codex at 5463682b15

- P1 1 staging root dropped at the commit point: fixed in da1a35acd. The
  staging root key stays until the migration completes
  (`recodeSystemBarrier`, `cmd/qrdbd/system_migrate.go:341`). Boot refuses a
  committed journal whose staging root key is missing while the canonical
  root key is not keyed (`refuseCommittedJournalWithoutStagingRoot`,
  `cmd/qrdbd/system_migrate.go:660`). Tests:
  `TestRecodeSystemBarrier_AdoptFailureKeepsStagingRootForBoot`,
  `TestRecoverInterruptedSystemMigration_RefusesMissingStagingRoot`.
- P1 2 plaintext WAL history kept by log recycling: fixed in 45aee9ac2. The
  seal store opens with log recycling off (`openSealStore`,
  `cmd/qrdbd/seal_subsystem.go:455`). `sealStoreRetirer.retireFiles`
  (`cmd/qrdbd/seal_subsystem.go:594`) rotates the WAL and waits until every
  file written before the retirement is deleted. Test:
  `TestRecodeSystemBarrier_SealStoreRetiresPlaintextHistory`.
- P1 3 retirement not retried after a failure: fixed in bcfb18e8c and
  dfcf7e91c. `sealStoreRetirer.Retire` (`cmd/qrdbd/seal_subsystem.go:504`)
  writes a durable marker first and deletes it only on success. Before a
  committed seal-store journal is cleared, `recoverSystemMigration`
  (`cmd/qrdbd/seal_subsystem.go:572`) writes the marker. It then runs any
  owed retirement and returns its failure, so the next boot retries. Test:
  `TestRecoverInterruptedSystemMigration_RetiresUnderDurableMarker`.

## Row verify Codex at d3f00b95b8

- P1-a failed first journal read taken as no pending migration: fixed in
  cd55c7d5a. `recoverSystemMigration` (`cmd/qrdbd/seal_subsystem.go`)
  returns the `LoadMigrationJournalFrom` error before the recovery runs;
  only an absent journal means nothing is pending. Test:
  `TestSealSubsystemRecoverInterrupted_JournalReadFailureStopsBoot`.
- P1-b failed recovery logged and boot continued: fixed in 6cc577208.
  `recoverSystemMigration` returns the `RecoverInterruptedMigration` error,
  so `initSealSubsystem` stops startup; the journal stays and the next boot
  completes the roll-forward. Test:
  `TestSealSubsystemRecoverInterrupted_RollForwardFailureStopsBoot`.

## Findings on the base

- `Client.SealStore()` already goes through `capability[T]`.
- `TestClient_CapabilityAccessors_ReturnTheTransport` fails untagged only on
  its `SQL` case (the embedded SQLProvider is `qrdb_sql`-tagged); with the
  Makefile's `test-sdk` tags it passes.
- The docs and `pkg/permission` state the seal store has no network route by
  design (node-local, in-process embedders only). Exposing it is an
  architecture change; the coordinator's resume order directs it.
