# Plan: #1647 SealStoreClient on every transport (docs/18 V12, SealStore half)

#1660 shipped the PermissionClient half. This row ships the SealStore half.

## Objective

`transport.SealStoreClient` answers on all six transports (embedded, grpc,
rest, quic, unix, mcp) instead of embedded only, gated server-side by
`permission.SealStoreManage` (`seal:store_manage`, ScopeCross, SO-exclusive),
the same permission the embedded transport checks.

## Slices

1. Shared remote client: `transport.SealStoreEndpoints` +
   `NewRemoteSealStoreClient` (`sdk/go/transport/seal_store_remote.go`),
   mirroring `permission_remote.go`. Refuses nil requests and empty names
   before the wire. Test: `seal_store_remote_test.go` (round trip, refusal
   without a wire call).
2. Server endpoints, one per listener, each gated by `seal:store_manage`:
   gRPC RPCs in `qrdb.proto` (regenerated), REST `/v1/seal-store/...`, QUIC
   `sealstore.*` methods, MCP `qrdb_seal_store_*` tools; the server holds a
   `*seal.SealStore` over the node barrier.
3. Client wiring on grpc, rest, quic, unix and mcp with
   `var _ transport.SealStoreClient` assertions.
4. E2E on each of the six transports (no sleeps); docs: SPEC.md SDK row,
   `sdk/go/doc.go`, identity-rbac and barrier-seal engineering docs (the
   "no network route" statements change).
5. CLI: `qrdb seal-store` verbs, CLI E2E on every network transport and an
   embedded CLI test (fs1647a).
6. Refusal E2E: a tenant identity without `seal:store_manage` is refused every
   seal store call with the transport's typed permission denial over the SDK
   and the CLI on every network transport; CHANGELOG entry; stale "gRPC and
   unix" comments corrected (dr1647q). The QUIC seal store and permissions
   clients return the `t.call` error as-is, so a refused call keeps its wire
   status (dr1647r).
7. Lane-verify Codex security P1s closed (fr1647n, fr1647o, fr1647p): secret
   guard (https only, no redirect) on REST/MCP put and get; the seal store
   migrated by `recodeSystemBarrier` on `enable-encryption`; atomic,
   serialized reseal; the secret-name rule on the server
   (`seal.ErrInvalidSecretName`) and in the SDK before the wire
   (`transport.ErrSealStoreInvalidName`). Tests: `pkg/seal/seal_store_test.go`,
   `TestRemoteSealStoreClient_RefusesInvalidNamesBeforeTheWire`,
   `TestRemoteSealStoreClient_AcceptsOpaqueNames`.
8. `seal.ErrInvalidSecretName` is classed InvalidArgument in
   `pkg/api/errclass/table.go`, so every transport answers invalid-argument
   (REST 400, gRPC/Unix InvalidArgument, QUIC `StatusInvalidArgument`, MCP the
   invalid-argument tool code); REST's local special case is deleted (fr1647q).
   Tests: `TestGRPC_SealStore_InvalidNameIsInvalidArgument`,
   `TestUnix_SealStore_InvalidNameIsInvalidArgument`,
   `TestSealStoreOverQUIC_Errors/invalid name`,
   `TestSealStoreTools_InvalidNameIsInvalidArgument`.
9. Typed seal-store refusals (sr1687b): a missing secret, an invalid name and
   a sealed seal-store barrier keep their seal sentinel under `errors.Is` on
   gRPC, Unix, REST, QUIC and MCP, as embedded, through three structured
   refusal reasons in `sdk/go/transport/refusal.go`. Tests: see
   "sr1687b: typed seal-store refusals" below.

## Codex round 1 at e8e60cade2

  empty read after committing the staged seal-store records, then deleted
  the staging key and cleared the journal. Fix:

  reads the staging root key (and its wrapped key) before the first swap and

  `TestRecoverInterruptedMigration_ShamirWrappedKeyAdoptedBeforeEnvelope`,
  `_ShamirWrappedPutFails`,
  `TestMintKeyedShamirSibling_WrappedBlobValidAtCanonicalPath`.

## sr1687b: typed seal-store refusals

A remote seal-store caller got a missing secret as
`*transport.KeyNotFoundError` (gRPC, Unix) or a generic status error (REST,
QUIC, MCP), where embedded returns the seal sentinel. Fix: three rows in the
structured-refusal table (`sdk/go/transport/refusal.go` `barrierRefusals`):

- `ReasonSealStoreSecretNotFound` = `SEAL_STORE_SECRET_NOT_FOUND` for
  `seal.ErrSealStoreSecretNotFound`;
- `ReasonSealStoreInvalidSecretName` = `SEAL_STORE_INVALID_SECRET_NAME` for
  `seal.ErrInvalidSecretName`;
- `ReasonSealStoreBarrierSealed` = `SEAL_STORE_BARRIER_SEALED` for
  `seal.ErrSealStoreBarrierSealed`.

`errclass.Refusal` emits them through `barrierRefusal` for a
`*seal.SealStoreError` wrapping each sentinel, and every server already writes
seal-store errors through its shared error writer, so no handler changed.
Commit "fix(sdk): carry seal-store refusals as structured reasons so every
transport rebuilds the seal sentinel (#1647)". Tests:
`TestRefusal_barrierSentinels` (three SealStoreError cases),
`TestRefusalError_SealStoreSentinels`, `TestGRPCSealStore_ServerErrors` (with
a sealed-barrier case), `TestUnixSealStore_ServerErrors`,
`TestRESTSealStore_MissingSecretIsSealStoreNotFound`,
`TestE2E_SealStoreMissingSecretIsSealStoreNotFound` (QUIC),
`TestMCPSealStore_MissingSecretIsSealStoreNotFound`, and the e2e
`TestSealStore_SDK_PerProtocol` (get and delete of a missing name) and
`TestSealStore_CLI_PerProtocol` (get after delete names the missing secret).

## Codex round 2 at 1eda087455

- P1-a a Shamir roll-forward took a not-found, empty or (nil, nil) read of
  the staged wrapped key as "not Shamir", overwrote the live records and
  adopted an envelope that cannot recover the root key. Fix: 4633d653e "a
  Shamir migration roll-forward requires a nonempty staged wrapped key".
  `database.RecoverInterruptedMigration` (`pkg/database/migrate_node.go`)
  takes the target from the staging envelope's strategy (`strategyOf`) or
  the journal's `TargetStrategy`; for Shamir a missing, nil or empty staged
  wrapped key returns `ErrMigrationStagingRootUnreadable` before anything is
  swapped, copied, deleted or cleared. Tests:
  `TestRecoverInterruptedMigration_ShamirWrappedKeyMissing`,
  `_ShamirWrappedKeyEmpty`, `_ShamirWrappedKeyNilNil`,
  `_PassphraseWrappedKeyNilNil` (a passphrase target still completes).
- P1-b an embedded node logged a refused recovery and kept starting, so later
  writes were lost when a retry swapped the keyed copies in. Fix: f3aec710c
  "a refused migration recovery stops the embedded node's startup".
  `buildNodeSealSubsystem` (`sdk/go/node/node.go`) closes the seal store and
  returns a `StorageCreateError` (backend "seal-recover") wrapping the error,
  as the daemon's `recoverSystemMigration` does; the journal stays, so the
  next start retries. Test:
  `TestBuildNodeSealSubsystem_RecoveryRefusalStopsStartupAndRetries`.
