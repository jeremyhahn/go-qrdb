# Plan: SQLite VFS backend, tier 1 (#926)

## Objective

Build the first build slice that
[../decisions/sqlite-vfs-build.md](../decisions/sqlite-vfs-build.md)
("First build slice the recommendations imply") implies: a pure-Go page store
in the root module that maps one SQLite database file onto the
`sqlite/<db>/meta` and `page/<pgno>` keyspace with snapshot-pinned reads, a
one-proposal commit, the staged commit and publish for oversized transactions
(Q2 A), a serialized writer through a distributed lock with `SQLITE_BUSY` on
contention (Q3 A), the restore generation check (Q4 A), quota accounting with
`SQLITE_FULL` and the `sqlite-vfs` entitlement (Q5 A); then a tier 1 binding
on `modernc.org/sqlite` registering VFS `qrdb` (Q1 A), tested end to end by a
stock SQLite application on every transport.

Rulings: Q1-Q5 A adopted (Tenant Agent ruling 1115, 2026-11-22); the SQLite
engine dependency `modernc.org/sqlite` approved by owner ruling 1234 (owner
queue 288) and in.

## Slices (in order)

1. Page store core (sr926a, done): keys, meta record, `Txn` over `Backend`,
   `MVCCBackend`; unit tests of keys, meta, reads, writes, truncation,
   snapshot isolation and atomic commit.
2. Staging and generation (sr926b, done): staged commit and one publish above
   the stage threshold, meta restore generation, `ErrSnapshotChanged` at Begin
   and Commit, `Store.BumpGeneration`; unit tests of staged commit, publish
   and stage failure cleanup, generation change.
3. Writer lock, change counter, stage sweep (sr926c, done):
   `WriterLock` over `lock.Locker`, `Txn.Reserve` (xLock RESERVED) with
   `ErrBusy` at once on contention, `ErrBusy` at Commit on a lost lease, the
   meta change counter so a stale snapshot cannot reserve, and the sweep of
   stages a crashed writer left; unit tests with an in-package `lock.Locker`.
4. Server-side prefix-move publish op (sr926d, done):
   `protocol.OpMVCCMovePrefix` behind the `prefix-move` cluster feature,
   `MVCCKVService.MovePrefix`, and its rewrites in the namespace,
   hard-confinement and quota wrappers; one revision, a live-count mismatch
   writes nothing.
5. Page store publish over `MovePrefix` and a service-backed Backend (sr926e
   and sr926f, done).
6. Deps step: add `modernc.org/sqlite` to `go.mod` (its own step) (rw926w1,
   done: v1.63.0, owner ruling 1234).
7. Tier 1 binding and VFS `qrdb` registration (Q1 A) (rw926w1, done:
   `pkg/sqlitevfs/moderncvfs`; see "## rw926w1"): batch-atomic, no WAL,
   no `xShmMap`, the true journal mode reported; error mapping
   (`ErrBusy` to `SQLITE_BUSY`, `ErrSnapshotChanged` to
   `SQLITE_BUSY_SNAPSHOT`).
8. Server wiring (sr926g, done): the writer lock over the server's
   lock service (`NewLockServiceWriter`), and a Store over a (tenant,
   database) scope's resolved MVCC, transaction and lock services, its commit
   and staged publish one proposal each through the service-backed Backend,
   proven on the prefix, volume and raft isolation types. Open for the owner:
   - (o1) where and by whom the server constructs a Store for a caller
     (registry accessor, embedded-server SDK surface or transport op).
   - (o2) the holder ID a database's writer takes (per connection, process
     or node) and the default lease TTL. Decided by convention (ruling 109):
     per connection, and the lease TTL is the lock service's default TTL.
   - (o3) whether the Backend carries a per-call context instead of
     ServiceBackend's construction-time context. Decided by convention
     (ruling 109): the Backend takes a per-call context. Built (sr926j): every Backend method takes a context.Context, and Store.Begin pins the transaction's read context.
   - (o4) whether the prefix-move op is wrapped in OpGuarded. Decided by
     convention (ruling 109): it is OpGuarded. Built (sr926j): the namespaced view's MovePrefix carries the database's drop-fence guard, so the move is one OpGuarded entry, proven by a drop racing a staged publish.
9. Quota and `SQLITE_FULL` (sr926h and sr926i, done): a commit or publish past
   the tenant's storage quota fails with `ErrFull` (the binding maps it to
   `SQLITE_FULL`) and leaves the database whole, proven on the prefix, volume
   and raft isolation types. The per-tenant database count cap and the
   `sqlite-vfs` entitlement gate a database's creation. They are built as a
   gate that takes its inputs (slice 9b, rw926c below), and the admin
   surface that sets both on every transport, the CLI and config defaults is
   built (slice 9c, rw926d below); only the gate's caller, where the server
   constructs a Store (o1), waits on the owner's answer.
10. Optimistic mode (`qrdb_concurrency=optimistic`, Q3) (rw926a, done):
   `WithOptimistic`, the opt-in alternative to `WithWriterLock` (the two are
   exclusive: `ErrOptimisticWithWriterLock`). A transaction records every page
   it reads from its snapshot, including pages read as absent, as a
   `ReadCheck` set. `Backend.Commit` and `Backend.Publish` check it
   atomically with the write: `MVCCBackend` under its lock, and
   `ServiceBackend.Commit` as compares in the commit's own transaction. A
   changed read fails with `ErrSnapshotChanged` and writes nothing. Unit
   tests cover disjoint writers, an overlapping read, an absent page created
   concurrently, a staged commit conflicting at publish (its stage keys
   swept), and the conflict over the service. Departures and open items:
   - The meta key is checked at the commit-time revision, not the snapshot
     revision. Every commit rewrites meta, so a snapshot-revision check would
     make every pair of writers conflict. This check makes the generation check
     atomic with the write for any Store without a writer lock. Optimistic mode
     conflicts instead on a moved page count or page size, and advances the
     change counter from the newest meta record.
   - (o5, closed by rw926b) `OpMVCCMovePrefix` carries compares, which the
     engine evaluates at apply before it reads the source range, atomically
     with the move; a failed one answers a guard refusal
     (`*service.WriteGuardRefusedError`) and writes nothing.
     `ServiceBackend.Publish` sends the read set as those compares and maps
     a failed one to `ErrSnapshotChanged`, so a staged commit over the
     service without a writer lock is read-checked, not refused. The
     compares travel in the existing
     op behind the `prefix-move` feature. Tests: protocol roundtrip and
     truncations, engine failed-compare and absent-key compares, service
     and wrapper handling, `TestOptimistic_ServiceStagedPublishConflicts`,
     and `TestSQLiteVFSWiring_OptimisticStagedPublishChecksReads` on the
     prefix, volume and raft isolations.
   - (o6) SQLite rewrites page 1 (the file change counter at offset 24) on
     every write transaction. Once the binding (slice 7) runs, two optimistic
     SQLite writers therefore always overlap on page 1 and conflict, even when
     their data pages are disjoint. Concurrent optimistic writers need the
     binding to exclude the header's change-counter bytes from the read check,
     or to serve them from the meta change counter. Decided in slice 7
     (rw926w1): served from the meta change counter (see "## rw926w1").
11. CLI end-to-end tests per the test standard on every transport (gRPC,
   QUIC, Unix, embedded): commit, contention and busy-retry, a `VACUUM`
   above the stage threshold, restore to a revision, quota exhaustion.

  registry accessor, SDK surface or transport op constructs a Store.
- The proto, REST, gRPC, QUIC, MCP, CLI and SDK fields for

one-line `go.mod` commit marks `modernc.org/libc` direct, because the
binding's callbacks take `*libc.TLS` (no module or version change; departure
from the brief's "no later go.mod commit", made so `go mod tidy -diff` stays
clean).

Package `pkg/sqlitevfs/moderncvfs`: `Register(open Opener) error` registers a
raw `sqlite3_vfs` named `qrdb` once per process (`ErrRegistered` on a second
call; `Unregister` for tests); `Opener` maps the `file:` URI path and its
query parameters (`ConcurrencyParam`, `qrdb_concurrency`, among them) to a
`*sqlitevfs.Store`. modernc's own `vfs` package is not used: it picks the VFS
name, owns locking and passes no URI parameters. Every pointer conversion is
in `abi.go`, each `#nosec G103` with its ABI fact. `pkg/sqlitevfs` gains
`Txn.ChangeCounter` (unit test `TestTxnChangeCounter`).

Tests (`vfs_test.go`): `TestVFS_CreateInsertSelect`,
`TestVFS_RollbackLeavesDatabaseUnchanged`, `TestVFS_ReopenReadsCommittedRows`,
`TestVFS_CommitIsOneRevision`, `TestVFS_JournalModeWALNotEntered`,
`TestVFS_BusyOnWriterContention`, `TestVFS_SnapshotChangedIsBusySnapshot`,
`TestVFS_FullIsSQLiteFull`, `TestVFS_VacuumAboveStageThreshold`,
`TestVFS_OptimisticDisjointWriters`, `TestVFS_RegisterTwiceRefused`; error
codes checked through the modernc `*sqlite.Error` `Code()`.

Choices and departures:

- Batch atomic is not reachable: this modernc build is compiled without
  `SQLITE_ENABLE_BATCH_ATOMIC_WRITE` (checked with `pragma
  compile_options`), so the pager ignores `SQLITE_IOCAP_BATCH_ATOMIC`, keeps
  a rollback journal and never sends the atomic-write file controls. The
  binding still answers BATCH_ATOMIC and handles BEGIN/COMMIT/ROLLBACK
  ATOMIC_WRITE (COMMIT answers non-IOERR codes; everything else
  `SQLITE_NOTFOUND`), and commits instead at the database file's `xSync`
  while it holds RESERVED or above, or at the drop to SHARED with
  `synchronous=OFF`; the drop to NONE rolls back. After a failed commit the
  file ignores writes and syncs until the unlock, so journal playback is a
  no-op.
- Journal and temporary files (the architecture is silent): the brief's
  default refuses a main-journal open, but without batch atomic every write
  transaction needs one, so the main journal is served in memory per open
  and dropped at close; `xAccess` reports no file, so a journal is never hot,
  and `xDelete` answers OK. Temporary files, the subjournal and temp
  databases go to the OS VFS; super-journal and WAL opens are refused.
  io_methods is version 1 (no `xShmMap`), so `journal_mode=WAL` is not
  entered.
- Locks: SHARED begins a `Txn`, RESERVED (and above) calls `Txn.Reserve`;
  `xCheckReservedLock` answers 0. Lock state is per connection: nothing
  coordinates connections inside the process beyond the page store.
- o6: header bytes 24-27 (file change counter) and 92-95 (version-valid-for)
  are stored as zeros and served from `Txn.ChangeCounter()`; a page-1 write
  equal to the stored bytes after masking is skipped, so page 1's key
  revision moves only when the header really changes, and two optimistic
  writers on disjoint tables both commit. Bytes 96-99 (the SQLite version
  number) are stored as written: they do not change per transaction.
- Errors: one table (`errors.go`): `ErrBusy` to `SQLITE_BUSY`,
  `ErrSnapshotChanged` to `SQLITE_BUSY_SNAPSHOT`, `ErrFull` to `SQLITE_FULL`,
  anything else to the call's `SQLITE_IOERR_*` (`SQLITE_ERROR` for
  COMMIT_ATOMIC_WRITE).

Open: (o7) a connection that keeps SHARED after its write transaction (an
open read statement) reads from a fresh snapshot, not one pinned at its own
commit, so its page cache may mix revisions. (o8) a user `ROLLBACK` after a
cache spill can play the journal back and sync, which commits the restored
pages: the data is unchanged but one extra revision is written (not
tested). Nothing in the server opens the VFS yet. o7 and o8 are closed in
"## rw926w2".

- `go test -count=1 -tags=codec_json,raft ./pkg/sqlitevfs/...`: ok, ok.

Open:

- (o9) the bump is a second write after the restore's own. A commit that
  lands between the two is never overwritten (the bump's read check refuses
  a moved meta and retries past it), but a transaction that begins in that
  window is not told of the restore when the restored generation equals the
  one its Store saw: SQLite may trust a page cache from before the restore
  (the restore put back an older header change counter), and that
  transaction's commit is not refused. Every transaction that begins after
  the bump is told. The window cannot be closed
  in the wrapper without changing the restore op. Options: (a) the restore
  op writes each touched database's meta bump in the restore's own
  revision (a server op and protocol change); (b) the wrapper takes each
  database's writer lock around a dry run and the restore (does not cover
  the optimistic mode or stores without a lock, and the lock is advisory);
  (c) accept the window and document it. Recommendation: (a), the only one
  that makes the restore and the bump one atomic revision on every mode.
  Closed in rw926w5 (below).
- (o1) still open: nothing in the server constructs a Store for a caller,
  calls `sqlitevfs.Admit` or registers `CountDatabases`. Recommendation: an
  embedded-server SDK surface first (no wire change; `Admit` and the
  `CountDatabases` counter called there), then a transport op for remote
  callers as a later row. Server half closed in rw926w5 (below); the client
  half is open.

## rw926w5

o9 closed and the server half of o1.

Decisions:

- o9, decided by convention (ruling 109): option (a) in substance with no
  wire change. The restore hook restores each touched database through its
  page store, so the restore and the bump are one revision on every mode.
  (b) is refused, since the writer lock is advisory and does not cover
  optimistic stores. (c) is refused because SPEC is the contract.
- o1, server half, decided by the architecture record (the Store lives in
  the application): the server gates the write that creates a database.
  That write is admitted by `sqlitevfs.Admit` and counts +1 in
  `sqlite_databases` usage; a drop counts -1. The registry and the
  lifecycle quota service register that counter.

Built, one commit per slice:

- `pkg/sqlitevfs`: `Store.RestoreToRevision(ctx, rev)` replaces
  `BumpGenerationAfterRestore`. In one commit, holding the writer lock when
  the Store has one, it writes rev's pages and meta record and sets the generation one past the
  larger of the current and the restored one. The same commit deletes the
  stage keys a Store without a lock left live. A database absent at rev is
  removed (meta, pages and stage keys). A moved database is retried up to
  8 times, then it is `ErrSnapshotChanged`. Tests:
  - `TestStoreRestoreToRevision_OneRevision`
  - `_StagedAboveThreshold`
  - `_OpenTxnIsSnapshotChanged`
  - `_RemovesDatabaseAbsentAtRev`
  - `_RecreatesDatabase`
  - `_NoChangeWritesNothing`
- `pkg/server/sqlitevfs_restore.go`: the hook splits a restore. Keys
  outside `sqlite/` go through the MVCC service. Each database goes through
  `Store.RestoreToRevision`. A database that is busy or that moved is
  reported as a conflict, unless Force is set, in which case its error is
  returned. Tests on the prefix, volume and raft scenes:
  - `TestSQLiteVFSRestore_DatabaseRestoredInOneRevision`
  - `TestSQLiteVFSRestore_MixedKeysRestoresBoth`
- `pkg/server/sqlitevfs_admit.go`: `withSQLiteAdmission` puts the gate on
  a scope's transaction service (`Execute`, `ExecuteWithMode`) and its
  MVCC `MovePrefix`.
  - A put of `sqlite/<db>/meta` while none is live is admitted first, and a
    refusal returns Admit's error and writes nothing.
  - An applied create counts +1 and a delete of a live meta record -1.
  - The system tenant records nothing, and a recorder error is not
    returned (the count is soft).
  - Tests on the prefix, volume and raft scenes:
    - `TestSQLiteAdmitTxn_EntitlementOffRefusesCreate`
    - `TestSQLiteAdmitTxn_CapReachedRefusesCreate`
    - `TestSQLiteAdmitTxn_ExistingDatabaseOpensWithoutChecks`
    - `TestSQLiteAdmitTxn_CreateAndDropRecordUsage`
    - `TestSQLiteAdmitMovePrefix_StagedCreateIsGated`
- `pkg/server/rest_registry.go`: `newSQLiteAdmission` builds the gate when
  the tenant service checks entitlements, provides quotas and records
  usage. It wraps a `quota.Service` whose `sqlite_databases` counter reads
  the persisted usage. `applyQuota` applies the gate after the restore

## rw926w9

Built, one commit per slice:

- Write refusals cross the wire. `errclass` encodes the write-guard refusal
  (`WRITE_GUARD_REFUSED`), the command conflict (`COMMAND_CONFLICT`), the
  quota refusal (`QUOTA_EXCEEDED`) and the entitlement refusal
  (`ENTITLEMENT_DENIED`) as a reason plus metadata.
  - Each encoder is guarded by the error class.
  - `pkg/service` and `pkg/quota` gain `Metadata()` and `*FromMetadata`.
- `sdk/go/sqlitevfs`:
  - `NewBackend(mvcc, txn)` is the page store's `ServiceBackend` over the Go
    SDK client.
  - `NewWriterLock(lock, holder, ttl)` is the writer lock over the SDK lock
    client.
  - `wireError` rebuilds a typed refusal from a `RequestError` reason while
    keeping the wire error in the chain, so an over-quota commit is
    `ErrFull`.
  - The package imports no modernc package.
  - Tests: `TestClientBackend_*` and `TestClientWriterLock_*`.
- `qrdb sqlite`:
  - `exec <db> <sql>` prints the rows affected.
  - `query <db> <sql>` prints rows as a table, JSON or YAML.
  - `restore <db> --revision R [--dry-run] [--force]` restores
    `sqlite/<db>/`.
  - `--concurrency lock|optimistic` (default lock) and `--stage-threshold`
    reach the Opener as URI parameters.
  - `SQLITE_BUSY` exits with code 5 and `SQLITE_FULL` with code 13.
  - Tests: `TestSQLiteCmd_*` (the standalone server in memory).

Decisions (by convention, ruling 109):

- The server refuses a lock of no lease, so `NewWriterLock` defaults a ttl
  of 0 to `DefaultWriterLockTTL` (30s). The wire carries whole seconds, so
  a ttl under one second is `ErrInvalidOption`.
- Lock outcomes already cross every wire typed, so the lock adapter passes
  them through. Only the write refusals needed reasons.
- The CLI registers VFS qrdb once per process. Its Opener reads the
  connected client at open time and holds the writer lock as
  `qrdb-cli/<host>/<pid>`. Each command opens a single connection.
- A command exits with the code its error reports through an
  `ExitCode() int` method, which is SQLite's own result code.
