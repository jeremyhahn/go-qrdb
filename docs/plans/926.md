# Plan: SQLite VFS backend, tier 1 (#926)

## Objective

Build the first build slice that
[../decisions/sqlite-vfs-build.md](../decisions/sqlite-vfs-build.md)
("First build slice the recommendations imply") implies: a pure-Go page store
in the root module that maps one SQLite database file onto the
`sqlite/<db>/meta` and `page/<pgno>` keyspace with snapshot-pinned reads, a
one-proposal commit, the staged commit and publish for oversized transactions
(Q2 A), a serialized writer through a distributed lock with `SQLITE_BUSY` on
contention (Q3 A), the restore generation check (Q4 A), quota accounting with
`SQLITE_FULL` and the `sqlite-vfs` entitlement (Q5 A); then a tier 1 binding
on `modernc.org/sqlite` registering VFS `qrdb` (Q1 A), tested end to end by a
stock SQLite application on every transport.

Rulings: Q1-Q5 A adopted (Tenant Agent ruling 1115, 2026-11-22); the SQLite
engine dependency is pending the owner (owner queue 288); no engine import
until he answers.

## Slices (in order)

1. Page store core (sr926a, done): keys, meta record, `Txn` over `Backend`,
   `MVCCBackend`; unit tests of keys, meta, reads, writes, truncation,
   snapshot isolation and atomic commit.
2. Staging and generation (sr926b, done): staged commit and one publish above
   the stage threshold, meta restore generation, `ErrSnapshotChanged` at Begin
   and Commit, `Store.BumpGeneration`; unit tests of staged commit, publish
   and stage failure cleanup, generation change.
3. Writer lock, change counter, stage sweep (sr926c, done):
   `WriterLock` over `lock.Locker`, `Txn.Reserve` (xLock RESERVED) with
   `ErrBusy` at once on contention, `ErrBusy` at Commit on a lost lease, the
   meta change counter so a stale snapshot cannot reserve, and the sweep of
   stages a crashed writer left; unit tests with an in-package `lock.Locker`.
4. Server-side prefix-move publish op (sr926d, done):
   `protocol.OpMVCCMovePrefix` behind the `prefix-move` cluster feature,
   `MVCCKVService.MovePrefix`, and its rewrites in the namespace,
   hard-confinement and quota wrappers; one revision, a live-count mismatch
   writes nothing.
5. Page store publish over `MovePrefix` and a service-backed Backend (sr926e
   and sr926f, done).
6. Deps step: add `modernc.org/sqlite` to `go.mod` (its own step) (blocked:
   owner queue 288).
7. Tier 1 binding and VFS `qrdb` registration (Q1 A) (blocked: owner queue
   288): batch-atomic, no WAL,
   no `xShmMap`, the true journal mode reported; error mapping
   (`ErrBusy` to `SQLITE_BUSY`, `ErrSnapshotChanged` to
   `SQLITE_BUSY_SNAPSHOT`).
8. Server wiring (sr926g, done): the writer lock over the server's
   lock service (`NewLockServiceWriter`), and a Store over a (tenant,
   database) scope's resolved MVCC, transaction and lock services, its commit
   and staged publish one proposal each through the service-backed Backend,
   proven on the prefix, volume and raft isolation types. Open for the owner:
   - (o1) where and by whom the server constructs a Store for a caller
     (registry accessor, embedded-server SDK surface or transport op).
   - (o2) the holder ID a database's writer takes (per connection, process
     or node) and the default lease TTL. Decided by convention (ruling 109):
     per connection, and the lease TTL is the lock service's default TTL.
   - (o3) whether the Backend carries a per-call context instead of
     ServiceBackend's construction-time context. Decided by convention
     (ruling 109): the Backend takes a per-call context. Built (sr926j): every Backend method takes a context.Context, and Store.Begin pins the transaction's read context.
   - (o4) whether the prefix-move op is wrapped in OpGuarded. Decided by
     convention (ruling 109): it is OpGuarded. Built (sr926j): the namespaced view's MovePrefix carries the database's drop-fence guard, so the move is one OpGuarded entry, proven by a drop racing a staged publish.
9. Quota and `SQLITE_FULL` (sr926h and sr926i, done): a commit or publish past
   the tenant's storage quota fails with `ErrFull` (the binding maps it to
   `SQLITE_FULL`) and leaves the database whole, proven on the prefix, volume
   and raft isolation types. The per-tenant database count cap and the
   `sqlite-vfs` entitlement gate a database's creation, which is where the
   server constructs a Store (o1): they wait on the owner's answer to o1.
10. Optimistic mode (`qrdb_concurrency=optimistic`, Q3): the read-set
   conflict check.
11. CLI end-to-end tests per the test standard on every transport (gRPC,
   QUIC, Unix, embedded): commit, contention and busy-retry, a `VACUUM`
   above the stage threshold, restore to a revision, quota exhaustion.

## Out of scope

- Tiers 2 and 3 of the architecture.
- Export/import as a migration tool (Q4 B).
