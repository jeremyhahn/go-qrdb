# #924 object-storage-lsm: plan

## Objective

An `objstore` database becomes the `pebble` engine whose SSTables live in a
bucket, through Pebble v2's `objstorage/remote.Storage` over go-objstore
`common.Storage` (docs/storage-engines/architecture.md "Target design:
object-storage LSM segment layout"; docs/decisions/object-storage-lsm.md,
OS-0 to OS-7, PROPOSED).

## Slices, in order

1. **Adapter, unwired** (done). `pkg/storage/objstore/remote.go`:
   `Remote` implements `remote.Storage` over `common.Storage`, one object
   prefix per instance (OS-3 A), whole-object fetch with `ReadAt` served from
   the fetched bytes (OS-6 A interim; go-objstore has no ranged read).
   Tests (`remote_test.go`, go-objstore memory provider): `NewRemote`
   refusals; create/read round trip with `ReadAt` at start, mid, end and past
   end; `Size`; not-exist on every method after `Delete`; `List` with and
   without a delimiter; prefix isolation of two Remotes on one store; writer
   and reader `Close` semantics; a Pebble round trip (flush to shared
   objects, reopen, read back) proven first on `remote.NewInMem()`, then on
   the adapter. No CLI surface, so no CLI E2E or features.mk change.
2. **Encrypting wrapper** (OS-4 C, decided by convention, ruling 109): `pkg/storage/objstore/encremote.go` over the encfs object form `pkg/seal/encfs/object.go`. (done)
3. **`remotelsm.WithRemote`** (OS-2 A, OS-5 A, decided by convention, ruling 109): package `pkg/storage/pebble/remotelsm` (bound through `pebble.WithOpenHook`; `pkg/storage/pebble` keeps no `objstorage/remote` import, lean standalone gate) with the persisted CreatorID, a changed CreatorID refused with a typed `*CreatorIDError`, and the store format marker `pkg/storage/objstore/lsmformat.go` (version 3) refusing the flat layout. (done)
4a. **Composition, unwired**: `objstore.OpenStore` (archive tiers refused), `atrest.Encryptor.Barrier`, and `pkg/server/lifecycle/objstore_lsm.go` opening the Pebble engine over the store (prefix "lsm", locator "qrdb", barrier-encrypted when the barrier is on, a sealed barrier refused). (done)
4a2. **Local object cache, unwired** (OS-6 A interim): `objstore.CachedRemote` under the encrypting wrapper in the 4a opener; each object fetched at most once, written through on create, removed on delete. (done)
4a3. **Cache hardening, unwired** (done): one fetch per object under concurrent first reads, no cache file resurrected by a read racing `Delete`, object names that do not map to one cache file refused with `InvalidObjectNameError`, the cache dir fsynced after each rename.
4b. **Engine switch** (waits on the owner's OS-0 ruling): an `objstore` database opens the Pebble engine through 4a; delete the flat engine (`objstore.go`, `journal.go`, `batch.go`, `iterator.go`, `keys.go`); lift the per-database refusal (OS-7). CLI multi-transport E2E on the objstore feature target.

## Out of scope until the owner rules OS-0 and OS-7

Any config key or engine selection change; any change to the shipped flat engine or to `NewLocalStorage`; lifting the per-database or Raft hot-apply refusal (OS-7).
