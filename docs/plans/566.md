# Row #566: release readiness

## Objective

Make the test suite release-ready: one test per behaviour at the uppermost
layer that reaches it, no low-value tests, and less CI runner time, without
losing any behaviour's only test or dropping below the coverage gate
(COVERAGE_THRESHOLD=91 and the per-package ratchet). Folded #1331 (suite
audit, ruling 273(12)).

## Slices (in order)

1. Plan files: this file and `docs/plans/566-suite-audit.md` (audit table).
2. Suite audit, one package per checkpoint commit, slowest CI legs first:
   `make coverage` legs `tenant-lifecycle`/`tenant` (pkg/tenant), then
   `seal-barrier`/`seal` (pkg/seal), then `server-raft`/`server`
   (pkg/server), then the `make test-tags` packages by test time.
   Each removal is recorded in the audit table with the test that keeps
   the path. Sleeps that stand in for synchronisation in kept tests are
   replaced with a sync.
3. The coordinator measures runner-minutes from CI before and after.
4. Suite audit 2 (pkg/service): docs/plans/566-audit-2.md.
5. Suite audit 3 (cmd/qrdb, cmd/qrdbd): docs/plans/566-audit-3.md.
6. Suite audit 4 (pkg/server, pkg/server/lifecycle, pkg/database,
   pkg/seal, pkg/sql/provider): docs/plans/566-audit-4.md.
7. Suite audit 5 (pkg/api/rest, pkg/dao, pkg/statemachine, sdk/go):
   docs/plans/566-audit-5.md.
8. Readiness re-audit (2026-11-23): docs/release/readiness.md updated
   against the branch tip (go-enclave pin, workflow list and runner
   routing, gate counts); items 1, 2, 9, 10, 11 still not met.

Tests added: none by design; a kept test may absorb an assertion from a
removed duplicate so the path keeps its check.
