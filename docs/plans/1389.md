# #1389 — SDK client bearer tokens (sdk-client-bearer)

Consumer: go-quicbaas#2439. A host that registers a bearer authenticator with
`node.WithAuthenticators` needs its SDK clients to send the token without a
hand-set header.

## sb1389a

### What landed

- `sdk/go/transport/bearer.go`: `TokenSource`, `StaticTokenSource`,
  `BearerRoundTripper`, `BearerUnaryClientInterceptor` /
  `BearerStreamClientInterceptor`, and the errors
  `BearerRequiresTLSError`, `BearerForeignHostError` and `TokenSourceError`.
  `sdk/go/transport/transport.go` adds `Config.TokenSource`,
  `WithBearerToken` and `WithTokenSource`.
- Wiring:
  - REST wraps its shared and pinned clients.
  - MCP wraps its HTTP round tripper.
  - gRPC and Unix chain the interceptors, and a `WithDatabase` clone keeps
    them. Their `Connect` returns a bearer refusal as itself, not as "health
    check failed".
  - `quic.New` refuses the option.
- The root sdk mirrors the options in `sdk/go/options.go`.
- Tests:
  - `sdk/go/transport/bearer_test.go`.
  - `bearer_test.go` in `transport/{rest,grpc,unix,mcp,quic}`.
  - `sdk/go/options_test.go` (`TestWithBearerToken_*`, `TestWithTokenSource_*`).
  - `sdk/go/node/bearer_authenticator_test.go`, which now drives every network
    transport through the SDK option. The cases are a valid token, a counting
    source asked on every call, and no option or a wrong token refused as
    unauthenticated. Only the wrong-scheme case keeps the hand-set header.
- Docs: the "Client bearer tokens" section in `docs/identity-rbac/api.md`, and
  the CHANGELOG entry.

### Conventions (ruling 109)

- (a) A local `TokenSource` interface, `Token(ctx) (string, error)`, called
  once per request, with `StaticTokenSource`. No oauth2 import and no new
  dependency.
- (b) A connection without TLS is refused with
  `*transport.BearerRequiresTLSError`, and a REST/MCP host other than the
  configured one with `*transport.BearerForeignHostError`. Error text never
  contains the token.
- (c) A source error, an empty token or a token holding control bytes gives
  `*transport.TokenSourceError`.
- (d) `quic.New` returns `*transport.ConfigError{Field: "TokenSource"}`.
- (e) The embedded client has no bearer option; this is documented.

### Owner questions

- **Q1. QUIC needs a wire credential field.** The QUIC request frame has no
  field a bearer can travel in, so QUIC clients can only authenticate with
  mTLS.
  - Option A: add an authorization field to the QUIC request frame, and have
    the QUIC server fill the credential carrier from it.
  - Option B: leave QUIC mTLS-only and keep the refusal.
  - Recommendation: A, in a follow-up row, so the bearer works on every
    network transport.
- **Q2. SPEC row text.** The text of the `sdk-client-bearer` row in
  `docs/SPEC.md` is for Software to add; this lane does not edit SPEC.

## sb1389b

### What landed

- `sdk/go/driver/dsn.go`: `DSNConfig.TokenSource` (`transport.TokenSource`).
- `sdk/go/driver/connector_network.go`: `getOrCreateTransport` passes
  `transport.WithTokenSource(cfg.TokenSource)` when the field is non-nil.
- A defect found on the way and fixed in place: the connector passed the
  DSN's bare `host:port` to the REST client, which joins request paths onto
  its address as a base URL, so no `rest://` request could be formed. The
  connector now dials `https://host:port` with TLS and `http://host:port`
  without (`networkAddress`); `grpc://` is unchanged.
- Tests:
  - `sdk/go/driver/connector_network_test.go`:
    `TestNetworkConnector_TokenSourcePassedToTransport`,
    `TestNetworkConnector_NoTokenSourceSendsNoBearer` and
    `TestNetworkConnector_TransportAddress`, all on rest and grpc.
  - `sdk/go/driver/dsn_test.go`: `TestParseDSN_NeverSetsTokenSource`.
  - `sdk/go/node/bearer_sql_driver_test.go` (`qrdb_sql`):
    `TestSQLDriver_BearerAuthenticatesOnRESTAndGRPC`, against a node with only
    that protocol and the host bearer authenticator. The cases are a valid
    token running `SELECT 1`, a counting source asked on every query, no
    source or a wrong token refused as unauthenticated, and a plaintext DSN
    with a source refused without the source being asked.
- Docs: a paragraph in `docs/sql/engineering.md` and the CHANGELOG entry.

### Conventions (ruling 109)

- (a) The token is never read from DSN text. It is set in code as
  `DSNConfig.TokenSource` on a config from `ParseDSN`, then opened through
  `NewNetworkConnector` and `sql.OpenDB`.
- (b) The connector adds `transport.WithTokenSource` only for a non-nil
  source, so every TLS, foreign-host and token-source refusal is the
  transport's own typed error.
- (c) `embedded://` and node connections take no bearer.

### Left open

- The REST client's `Connect` health probe (`sdk/go/transport/rest/transport.go`
  `probe`) reports every failed probe as a `*transport.ConnectionError`, so a
  plaintext `rest://` connection with a bearer gets a "health check failed"
  error and not `*transport.BearerRequiresTLSError`. gRPC and Unix already
  return the refusal as itself. The fix is in the sb1389a file, which this
  slice does not edit.
- Q1 (QUIC credential field) and Q2 (SPEC row text) stay open.
