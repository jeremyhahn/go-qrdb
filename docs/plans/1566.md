# Plan: SPEC row `object-storage-credential-handle` (#1566)

## Objective

The object-storage backend's credential crosses the seam as the go-enclave
protected-memory credential handle, not a `map[string]string`:
go-objstore's `Storage.Configure` takes the handle (since v0.9.1-alpha), its
backends copy the credential out for the call and never retain it, and
go-qrdb's adapter (`pkg/storage/objstore`) passes the handle `pkg/cli`
already holds and never holds a plaintext copy (docs/SPEC.md row).

## Slices, in order

1. **Fold PR #1404, then split it** (handle destroyed on every error
   path; provider resources released on close and on a failed open).
   #1404 also carried #1424's per-database objstore open (the opener,
   `WithObjectPrefix`, namespace ownership, `Destroy`, `Guarded`/
   `Exclusive`). The code review of the row PR (round 1) asked for that
   enablement to leave this row: it belongs to the `object-storage-provider`
   row, which still refuses a per-database objstore
   (`database.InvalidBackendError`). The split restores that code and its
   docs to main; #1424's commits stay in the branch history for that row.
   Kept here: `credentials.go` and its tests, the integration S3 stub
   credential tests (`make integration-test-storage-engines`), and the
   go-objstore bump. Added after the review: `Engine.Close` holds a
   lifetime lock over every call (with a closed recheck under it) and
   releases each provider once after the last call; a failed `New` releases
   what it created (`pkg/storage/objstore/close_test.go`). A seal-enabled
   pebble Go SDK node reports no unencrypted store and refuses an objstore
   database (`sdk/go/node/objstore_database_test.go`).
   Status: done.
2. **Handle seam on a tagged go-objstore.** The adapter passes the
   go-enclave handles to `Storage.Configure(settings, common.Credentials)`
   and destroys them on every path, but pins go-objstore at the
   pseudo-version `v0.9.1-alpha.0.20261111054905-aed613658de5`. The row
   says the adapter change follows go-objstore's tagged release. The
   handle `Configure(settings, creds Credentials)` is already in the tag
   `v0.9.1-alpha` (2026-10-27, the newest tag on the proxy as of
   2026-11-13); the pin is a later commit for go-objstore #231. When
   go-objstore tags a release containing #231, bump to that tag alone
   (deps go alone). No code change expected; the S3 stub credential
   integration test proves it. That pin is a later commit of its own,
   outside this row's PR.
3. **SPEC flip**: done. The row is `shipped` in docs/SPEC.md, citing
   #1566; the row PR carries it.
