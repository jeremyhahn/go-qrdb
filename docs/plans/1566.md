# Plan: #1566 object-storage credential handle

SPEC row: object-storage-credential-handle.

## Objective

The object-storage engine (`pkg/storage/objstore`) holds a provider's
credential only as a go-enclave handle, destroyed on every path, and it
releases the providers it opened on every path: `Close` waits for the calls
in flight and releases each provider once, and a failed `New` releases what
it created.

## Slices, in order

1. **Release on every path** (this slice, go-objstore v0.9.1-alpha as
   pinned). `objcommon.Storage` has no `Close`, so release goes through a
   type switch on `Close() error` / `Close()`.
   - `Engine.lifeMu`: every public call holds it shared (`enter`), `Close`
     exclusive; lock order lifeMu, journalMu, writeMu. Internal `get` and
     `list` serve callers already inside (CompareAndSwap, scan,
     deleteRange), so no call re-enters.
   - `closeStores` releases each distinct provider once; `Close` is
     idempotent.
   - `New` releases the stores on an `openStores`, format-marker or
     journal-recovery failure; `openStores` releases the store it replaced
     and, on failure, the store it created.
   - `readFileHandle` seam in `credentials.go`.
   - Tests (`close_test.go`): Close waits for a read in flight; every call
     after Close is refused; each provider released once, Close idempotent;
     a failed New releases its provider.
     (`credentials_test.go`): the key handle is destroyed when the secret
     read fails.
2. **go-objstore bump** (separate PR, ruling 1039): the tagged go-objstore
   release whose `Storage` carries `Close`; the type switch then becomes a
   direct call.

## Out of scope

- go.mod / go.sum changes in slice 1.
- A second process writing the same bucket (no conditional put in the
  provider interface).
- `TestNew_RefusesInlineCredentialsBeforeARegisteredCreator` (register_test.go)
  fails under `-count>1` on the base: its provider name is registered once
  per process.
