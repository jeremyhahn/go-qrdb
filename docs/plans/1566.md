# Plan: SPEC row `object-storage-credential-handle` (#1566)

## Objective

The object-storage backend's credential crosses the seam as the go-enclave
protected-memory credential handle, not a `map[string]string`:
go-objstore's `Storage.Configure` takes the handle (go-objstore#16), its
backends copy the credential out for the call and never retain it, and
go-qrdb's adapter (`pkg/storage/objstore`) passes the handle `pkg/cli`
already holds and never holds a plaintext copy (docs/SPEC.md row).

## Slices, in order

1. **Fold PR #1404** (handle destroyed on every error path; provider
   resources released on close/destroy/failed open; dedicated-store cache
   keyed by tenant and name; per-database objstore open via the opener and
   `WithObjectPrefix`, from #1424). Merged with `git merge --no-ff` at its
   head; conflicts with main resolved keeping both sides.
   Tests it carries: `pkg/storage/objstore` (close, destroy, ownership,
   prefix, guarded, exclusive, namespace, credentials), `pkg/database`
   (factory_objstore), `pkg/server` (barrier services, lifecycle, typed
   errors), `cmd/qrdbd` (start_database_objstore), `sdk/go/node`
   (sealed_database), `pkg/util/filelock`, and the integration S3 stub
   credential tests (`make integration-test-storage-engines`).
   Status: merged; main's `database_defaults` and #1404's objstore
   backend factory both reach the qrdbd and Go SDK node managers.
2. **Handle seam on a tagged go-objstore.** #1404 already passes the
   go-enclave handles to `Storage.Configure(settings, common.Credentials)`
   and destroys them on every path, but pins go-objstore at the
   pseudo-version `v0.9.1-alpha.0.20261111054905-aed613658de5`. The row
   says the adapter change follows go-objstore's tagged release. The
   handle `Configure(settings, creds Credentials)` is already in the tag
   `v0.9.1-alpha` (2026-10-27, the newest tag on the proxy as of
   2026-11-13); the pin is a later commit for go-objstore #231, which
   #1404 builds on. When go-objstore tags a release containing #231, bump
   to that tag alone (deps go alone). No code change expected; the S3
   stub credential integration test proves it.
3. **Row PR closes**: mark the row `shipped` in docs/SPEC.md, update
   docs/storage-engines/ and CHANGELOG. #1404 carried that flip, but
   docs/SPEC.md is a protected path for the lane, so the merge kept the
   row `planned`; the row PR (or a lane with LANE_POLICY_ALLOW
   docs/SPEC.md) makes the flip.
