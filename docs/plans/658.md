# Row #658: run modes documented and guarded

## Objective

A data directory belongs to one run mode (standalone or raft). The
run-mode guard (`pkg/server/lifecycle/run_mode.go`, `ClaimRunMode`) records
the mode on first start and refuses a start in the other mode. The docs
(`docs/run-modes.md`, `docs/run-modes/`) describe the guard as it is built.

## Slices (Codex round 4, #1734)

1. Refuse an unknown mode before touching the data directory.
   `ClaimRunMode` returns `*RunModeInvalidError` for any mode other than
   standalone or raft (empty is raft) before it creates the directory, reads
   the marker or writes a temporary file.
   Tests: `TestClaimRunMode_InvalidModeRefused` (no marker, no `.tmp`, no
   directory created); `TestRunStart_InvalidRunModeRefused` in cmd/qrdbd.
2. Serialize the claim across processes. When no marker is present, the
   guard takes an exclusive `pkg/util/filelock` lock on
   `<dataDir>/.qrdb-run-mode.lock`, re-reads the marker under the lock and
   writes it only when it is still absent. The fixed `.tmp` name stays: the
   lock is held while it is written.
   Tests: `TestClaimRunMode_ConcurrentOppositeModes` (exactly one of two
   opposite first starts wins; the other gets `*RunModeMismatchError`).
3. Rewrite "Changing the mode of an existing data directory" in
   `docs/run-modes.md` around the guard: the refusal, the errors the daemon
   prints, the unknown-mode refusal, the fresh-directory remedy, and the
   unmarked-directory-from-an-earlier-build case.

## Out of scope

- Any migration between the standalone and raft stores (owner-bound).
- Compatibility handling for directories from earlier builds beyond the
  documented claim-on-first-start behaviour.
- docs/SPEC.md, pm/rows.md, go.mod, coverage baselines.
