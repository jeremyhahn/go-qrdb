# #1619: nightly clusterproof soak against a 3-node docker cluster

## Objective

The per-PR `test-clusterproof` job only unit-tests the harness. Run the real
proof (`make cluster-proof` soak runner, then `make cluster-proof-check`)
every night against a three-node cluster booted from the release image on
the CI runner, and keep the evidence bundle as an artifact.

## Slices

1. `PROOF_KEEP=1`: TestBOOT01 leaves the cluster running after a pass
   (`EnvKeep` const; the up-front Remove stays). Makefile exports it.
   Test: the container package still compiles and its unit tests pass.
2. `scripts/cluster-proof-ci.sh` with `render DIR IMAGE` (test CA and node
   certificates via openssl, PINs, inventory.json, targets.json,
   workload.json for local docker on network `proof`, 192.0.2.0/24),
   `up DIR` and `down DIR`.
   Test: `test/clusterproof/soak/ci_fixture_test.go` renders into a temp
   dir and loads all three files through the harness parsers.
3. Makefile `cluster-proof-ci`: up, soak with `PROOF_SEAL=none`, check the
   bundle. Faults the runner cannot express are left out of the default
   nemesis (named in the commit body).
4. `.github/workflows/ci.yml` job `clusterproof-soak` (nightly, schedule or
   workflow_dispatch), wired into ci-gate like `soak`; buildgates
   `nightlyTierJobs` lists it. Docs: user.md, cli.md.
5. Fault image: the release image has no iptables, so `render DIR IMAGE
   [FAULT_IMAGE]` writes FAULT_IMAGE as `fault_image`;
   `test/clusterproof/fault.Dockerfile` and `make cluster-proof-fault-image`
   build it; the nightly job builds and passes it.
   Test: ci_fixture asserts targets.json's `fault_image` is the third arg.
6. Codex round 1 on #1625: the exec wrapper ends with `"$@"`
   (nemesis.ArgvElement) so the fault argv reaches docker word by word, and
   `up` loop-mounts a `CLUSTERPROOF_DISK_MB` (default 1024) ext4 image on
   each `node-N/data` (`down` unmounts it), so disk-full stays on one node.
   Test: ci_fixture asserts the exec ends with `"$@"` and renders
   DefaultDiskFill through a RemoteTarget as separate words.
7. Codex round 2 on #1625: node certificates add the SAN
   `spiffe://qrdb.cluster/node/<ip>:63001` (the Raft address enrolment
   uses); the admin certificate is `/OU=system/CN=admin` with
   `spiffe://system/user/admin`, as the ceremony adopts it.
   Test: ci_fixture verifies the admin cert against the CA for clientAuth,
   CN/OU/keyUsage and auth.TenantFromClientCert; each node cert through
   spiffe.NodeFromCert and forward.NodeIdentity.
8. Reland after #1633 (BOOT-01 "node-1 knows no leader" on main): the
   soak also runs on a PR that changes `scripts/cluster-proof-ci.sh` or
   `test/clusterproof/` (preflight output `clusterproof`); buildgates
   accept that `if:` for clusterproof-soak. BOOT-01's failure log drops
   the `resource=admin:status` audit lines and keeps >=200 others
   (helper + unit test); cluster-proof-ci.sh writes every node's full
   `docker logs` to `logs/node-N.log`, beside `bundle/` (the manifest
   checks every bundle file), uploaded as clusterproof-node-logs. A
   failing preflight diff selects the soak (buildgates run the step).
9. disk-full heals a node that exited on ENOSPC: fill/free run through an
   optional `disk_exec` template (data volume, no `--net`), then the heal
   restarts (and unseals) the node; nemesis unit tests with a docker double.
10. The healed node then failed pebble WAL replay ("encfs: block
   authentication failed"): ENOSPC tore encfs's in-place rewrite of the
   WAL's trailing block, and every unclean power loss does the same (go-xkms
   #2290). Dropping the bad final block loses acknowledged records, since
   that block was rewritten after an earlier Sync (ruling 913, the #1637
   Codex P1). Ruling 956 fixes the cause: never overwrite bytes a Sync made
   durable. Pebble WALs (*.log) and MANIFESTs (MANIFEST-*) are written in a
   framed, seal-on-sync layout (header flag): each frame carries its
   plaintext length, sealed with its index and length as AEAD additional
   data, and the Write after a Sync starts a new frame. On open a torn,
   short or unauthenticated FINAL frame ends the log (it holds no
   acknowledged byte); an earlier frame that fails authentication refuses
   the open with ErrAuthFailed. Every other file keeps the fixed-size
   layout (sstables need ReadAt arithmetic). A WAL or MANIFEST in the old
   layout (a device's preserved WAL) opens with its torn final block as
   the end of the log; in that layout the tear already destroyed the
   block's previous content, which is why the framed layout exists.
   Tests: a power-cut filesystem wrapper (byte-granular tear of the
   in-flight write) over many seeds at file level and through Pebble
   (WAL and MANIFEST cuts, every acknowledged key read back), old-layout
   open, tamper and frame swap refused. The disk-full nemesis expects the
   node to recover with no acknowledged write lost.

## Out of scope

- Any change to the schedule cron.
- Running docker in the lane: the nightly run is the docker proof.
- Hardware faults the hosted runner lacks.
