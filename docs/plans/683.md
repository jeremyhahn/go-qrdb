# Plan: strict-tenant-isolation (#683), phase 11 — tenant-only backups

## Objective

A platform (system-tenant) principal may not back up or restore the
shard groups owned by a strict tenant. Platform shard backup is limited
to groups it may reach (the system shard and non-strict tenants'
groups). The strict tenant's own principal, holding the tenant-only
backup permission, backs up its own group and restores it.

## Slices (one commit each)

1. Red tests (pkg/service backup tests):
   - a platform principal's CreateBackup of a strict tenant's group is
     refused with BackupStrictTenantGroupError;
   - the same principal's CreateBackup of the system shard succeeds;
   - the strict tenant's principal backs up its own group and restores it;
   - a platform principal's RestoreBackup into a strict tenant's group is
     refused with the same error.
2. Service check in BackupService.CreateBackup and RestoreBackup: resolve
   each target shard's owner tenant and strict flag, refuse a caller that
   is not that tenant. Typed error in backup_errors.go, mapped to 403 by
   the transports whose mapping is per-error.
3. Docs: docs/backup-restore "Strict tenants" section.
