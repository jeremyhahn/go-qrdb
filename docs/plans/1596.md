# Plan: #1596 self-hosted Go caches off the runner temp dir

## Objective

On self-hosted pool hosts the Go build and golangci-lint caches move from
`$RUNNER_TEMP/ci-cache` (root filesystem, grew to 168 GB) to a persistent
directory on `/mnt/raid0`; hosted runners keep `$RUNNER_TEMP/ci-cache` with
actions/cache. `scripts/ci-cache-dir.sh` picks the directory.

## Slices

1. (done, bd71a0265) `scripts/ci-cache-dir.sh` + `scripts/ci-cache-dir_test.sh`;
   ci.yml points every stage at it; actions/cache on hosted runners only.
2. Codex round 1 (two P1 findings):
   - Eviction must not delete a directory a concurrent stage has
     bind-mounted. The cache lives in generations,
     `<base>/gen-<UTC stamp>/{gobuild,golangci}`, and `<base>/current` names
     the live one. Each job that selects a generation touches its
     `.last-use` marker. Past `CI_CACHE_MAX_GB` the job creates a new
     generation and switches `current` by atomic rename of a temp file. An
     old generation is deleted only once its marker is older than
     `CI_CACHE_RECLAIM_HOURS` (default 7, longer than the 6 h job limit);
     the current one and the job's own are never deleted. Selection,
     rotation and the reclaim decision run under `flock`; reclaimed
     generations are renamed to `trash-*` and deleted after.
   - Cleanup must remove container-owned (uid 10001) files. A helper,
     `scripts/ci-cache-clean.sh`, empties each directory as root in a `--rm`
     toolchain-image container (`find /c -mindepth 1 -delete`, only
     DAC_OVERRIDE and FOWNER, no network), then removes it with a plain
     `rm`; without docker or an image it is a plain `rm -rf`. A survivor is
     a `::warning::`, never a failed job. ci-cache-dir.sh and ci.yml's six
     "Remove the temp Go caches" steps call it.
   - Tests: rotation over the cap, reclaim only past the age, the current
     generation never deleted, pre-generation dirs by age, the legacy temp
     cache and a stage-owned generation through the helper (read-only dirs
     stand in for uid 10001, a fake `docker` for the container), helper
     failure warns with exit 0, and the real helper on a uid-10001 fixture
     when docker and a local image are available (skipped otherwise).
3. lane-verify Codex review (two P1 findings):
   - Security: stages ran the shared, mutable toolchain tag after
     `ci-image.sh load` verified an ID. `load` now prints the ID and records
     it for the tag in `CI_IMAGE_IDS` (default `$RUNNER_TEMP/ci-image-ids`);
     `in-toolchain-image.sh` runs the recorded ID in every create/run.
   - Reliability: the stage launch's chown walk runs once per generation
     under `flock` on `<gen>/.owner-lock` and writes `<gen>/.owner-ready`;
     a walk ignores ENOENT (concurrent `DiskCache.Trim`), fails otherwise.
   - Tests: ci-image_test (ID printed and recorded); in-toolchain-image_test
     (ID reaches create/run, bad record refused, ENOENT, marker skip).
4. lane-verify Codex P1: the remaining tag consumers. `ci-cache-clean.sh`
   runs the recorded ID (a non-`sha256:` record disables the helper); the
   integration load steps hand `IT_IMAGE=$ID` on, so Compose (Makefile
   treats a `sha256:` IT_IMAGE as prebuilt, never built) and the scan's
   `docker save` (which refuses a non-ID) name the ID. Tests: ci-cache-dir_test
   (ID run, RUNNER_TEMP record, bad record), ci-image_test (a replaced tag
   keeps the record), buildgates `ci_image_id_handoff_test.go` + mutations.
5. lane-verify Codex (fx1597c), three findings:
   - P1 security: the producer saved and pushed by the shared tag. `save`
     resolves the ID once and archives a per-run tag
     (`<image>-run-<run id>-<attempt>`) created from it, checked after the
     save; `load` verifies the archive's per-run tag; `push` takes the
     recorded ID and pushes `<hash>-main-<run id>-<attempt>` from it, checked
     after the push; teardown runs `untag`. Tests: ci-image_test retag during
     save and between save and push; buildgates producer gate + mutations.
   - P1 retention: self-hosted daemons kept every CI image. `prune 24`
     (always(), self-hosted only) ends each job that saves or loads an
     image; it removes CI tags older than 24 h by creation/last tag time,
     keeping images of running containers. It untags an old image's
     run-unique tags (per-run, pushed) by name first, since the daemon
     refuses removal by ID while two tags name it. Tests: ci-image_test
     prune (stub counts tag references), untag; buildgates prune gate +
     mutations.
   - P2: hosted cache saves needed CI_PUBLISH (a push to main, which runs
     on the pool), so none ever ran. They now run under `CI_CACHE_SAVE`,
     the nightly schedule on main, on hosted runners; ci_runners_test
     holds the expression and the save condition + mutations.
6. Merge main (rulings 841, 862, 879): main's runner split, image producers,
   CI registry pull/push and `pool-images` win; the branch keeps the cache
   placement, the prune and the ID record; `adopt` goes (main's pull steps
   hand on the ID). Codex P1: prune untagged the second and later
   content-hash tags of an expired image by name after an inspect, so a tag
   another job moved in between lost its fresh image. Prune now never
   removes a content-hash tag by name: when several name the image it runs
   `docker image rm --force <id>`, which untags only the references naming
   that ID at removal time. Test: ci-image_test moves the second tag just
   before the removal; the fresh tag keeps its image.
7. Codex round 1 on #1597, P1: prune raced a concurrent producer reusing an
   image past the bound (the Make targets' already-built path). An image
   lock (`ci-image.sh lock-file`, `CI_IMAGE_LOCK`, flock) is held shared by
   pin, save, load and the docker-build targets (check, reuse, pull, build,
   push), and exclusive by prune, which removes nothing when it cannot take
   it. The reuse path refreshes the tag time under the lock; prune keeps an
   image tagged since its snapshot. Tests: ci-image_test prune under a held
   lock, load under a prune's lock, the make targets' lock probe. The lock
   polls `flock -n` up to `CI_IMAGE_LOCK_WAIT`, never `flock -w`, which the
   toolchain image's BusyBox flock lacks; a flock that fails to run is an
   error, not a held lock. Tests: a BusyBox-like flock shim takes the lock
   and times out on a held one; a broken flock is reported as such.
8. Codex round 2 on #1597, two P1s: pool runner containers share the daemon
   but not a temp dir, so the default lock file goes on the host's data
   array (`$CI_CACHE_ROOT/gh-runner-cache`, else `$CI_CACHE_ROOT`) on a
   self-hosted runner; with neither and no `CI_IMAGE_LOCK`, prune keeps
   every image. The LAN registry pull, its ID check and its tag move into
   `ci-image.sh lan-pull`, under the shared lock; ci.yml's three pull steps
   call it. Tests: two runners with separate temp dirs share the lock; no
   shared lock keeps every image; a prune run from inside the pull removes
   nothing; a LAN pull refuses under a prune's lock.
9. CI red on #1597 (Devcontainer images): with no lock path (no writable
   cache dir) the Makefile's `ci-image-shared-lock` redirected `:` to "",
   and dash exits on a failed redirect of a special builtin. The macro now
   skips an empty path and probes writability in a subshell. Test:
   ci-image_test runs both docker-build targets under /bin/sh with an empty
   and an uncreatable lock path; each goes on with no error.
10. Codex round 2 on #1597: prune counted a registry-cache tag left by
    ci_registry_push (<registry>/qrdb-toolchain:<hash>) as foreign, so an
    expired cached image never aged out. ci_ref now strips a registry
    host[:port]/ prefix before matching the CI image names. Test:
    ci_image_prune_test prunes an expired image with a local and a
    registry-cache tag and keeps one with a registry-cache and a foreign tag.
11. Merge of main after #1641 (owner ruling 999: every job on
    ubuntu-latest, no pool legs). Main's text wins where the branch served
    the pool legs only: ci.yml's LAN pull steps are main's inline pull again,
    `ci-image.sh lan-pull` is gone (main removed `ci_registry_pull_id`), the
    LAN push is main's by tag, in-toolchain-image.sh drops the self-hosted
    CI_CACHE_DIR refusal and pool_cache_test.go stays deleted. The cache
    directory script, the cache save on the nightly schedule, the IID pin
    and the guarded self-hosted clean and prune steps stay.
12. Merge of main (ci.yml v1.47 runner labels, waiver categories) and the
    Codex P1 on prune: a digest-only reference (`<repo>:<none>`, left by a
    pull by digest) kept an expired CI image forever. Both listings skip it
    alike, a foreign one marks the ID foreign, and removal by ID passes
    --force when one names the ID. ci-image_test.sh case 12a7.
