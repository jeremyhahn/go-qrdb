# Plan: #1596 self-hosted Go caches off the runner temp dir

## Objective

On self-hosted pool hosts the Go build and golangci-lint caches move from
`$RUNNER_TEMP/ci-cache` (root filesystem, grew to 168 GB) to a persistent
directory on `/mnt/raid0`; hosted runners keep `$RUNNER_TEMP/ci-cache` with
actions/cache. `scripts/ci-cache-dir.sh` picks the directory.

## Slices

1. (done, bd71a0265) `scripts/ci-cache-dir.sh` + `scripts/ci-cache-dir_test.sh`;
   ci.yml points every stage at it; actions/cache on hosted runners only.
2. Codex round 1 (two P1 findings):
   - Eviction must not delete a directory a concurrent stage has
     bind-mounted. The cache directory becomes a set of generations
     (`gen.<id>/{gobuild,golangci}`) with a `current` pointer. A job takes a
     lease file in the generation it uses (under `flock`), and releases it
     when it expires or the job runs `ci-cache-dir.sh release`. Past
     the cap a new generation becomes current; an old generation is
     reclaimed only once it has no live lease (a lease older than
     `CI_CACHE_LEASE_MAX_MIN`, default 360, the GitHub job limit, is dead).
     Reclaim renames it to `trash.<id>` under the lock and deletes it
     outside the lock.
   - Cleanup must remove container-owned (uid 10001) files. Deletion tries
     a plain `rm`, then a privileged helper: a `--rm` container from the
     toolchain image as root with only DAC_OVERRIDE and FOWNER, the
     same pattern as in-toolchain-image.sh's chown helper. The legacy
     `$RUNNER_TEMP/ci-cache` goes through the same helper in the release
     step. Cleanup failures warn; they never fail the job.
   - Tests: lease kept across rotation, reclaim after release, stale lease
     expiry, a lease-holder's directory survives a concurrent rotation,
     unremovable files go to the helper (read-only dirs stand in for
     another uid; as root, files chowned to 10001), release removes the
     legacy temp cache, helper failure warns and keeps the job green.

## Out of scope

- Moving the runner's own `_work` or tool cache.
- Sizing raid0 or changing the 40 GB default cap.
