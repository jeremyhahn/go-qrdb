# #1731 SDK PINs as wipeable bytes

## Objective

Every SDK request that carries a PIN holds it as caller-owned wipeable
`transport.Secret` bytes, and every transport zeroes those bytes when the
call returns: on success and on every refusal, through the typed methods
and through the generic `Request` dispatch.

## Slices

1. PIN fields become `transport.Secret`; each PIN-carrying request type gets
   a nil-safe `WipePINs`. Test: `transport/pin_wipe_test.go` table covers
   every type.
2. Typed transport methods defer `req.WipePINs()`; embedded onboarding
   copies the SO PIN before it is wiped. Tests: per-transport wipe tests.
3. Generic `Request` dispatch (embedded, REST, unix) wipes any request that
   implements `WipePINs` on every return. Tests:
   `rest/request_pin_wipe_test.go`, `unix/request_pin_wipe_test.go`.
4. `BarrierSealRequest` gains `WipePINs` (Codex P1, round 7), so a REST
   `v1/barrier/seal` dispatch zeroes the SO PIN. Tests: the request-wiper
   table and the REST generic-dispatch table cover it. Swept every
   `Secret` field in `sdk/go/transport`: all request types now wipe, except
   `CreateTenantRequest.SOPin`, which is documented caller-owned.
