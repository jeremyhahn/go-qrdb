# Plan: #1353 — Devcontainer images credential from the repository

## Objective

The Devcontainer images job must take its registry credential from the
repository (`secrets.`/`vars.` in the workflow), not from a runner's env
file, and fail with a clear message when it is unset (CA m1982 item 5,
ruling 312). The issue closes when a `ci.yml` run on `main` is green past
Devcontainer images.

## Status: already resolved on main — no code slice

The GitHub Actions move (DS-7377) delivered this before this lane:

- `.github/workflows/ci.yml`, step "Push the devcontainer images to GHCR":
  `CI_REGISTRY_TOKEN: ${{ secrets.GITHUB_TOKEN }}` and
  `CI_REGISTRY_USER: ${{ github.actor }}`, with `packages: write` on the
  job. No runner env file is read.
- `scripts/ci-image.sh push` dies with
  "CI_REGISTRY_USER/CI_REGISTRY_TOKEN is empty: the run's token is not in
  the step's environment" when either is unset, and names a refused login.
- `test/buildgates/ci_image_digest_test.go` fails when the push step's
  `CI_REGISTRY_TOKEN` is anything but `${{ secrets.GITHUB_TOKEN }}` (a
  stored PAT included), or when the token leaks into a workflow or job env.
- `test/buildgates/ci_runners_test.go` fails when `RELEASE_REGISTRY`,
  `ci-registry.sh` or the rest of the self-hosted registry machinery
  comes back.
- Close condition met: `ci.yml` push run 43446067534 on `main`
  (8a6bb3118) concluded success, with Devcontainer images, both
  Devcontainer image jobs and CI Gate all success.

## Slices

None. The existing gates above are the tests. This plan is the whole
change, so the merge closes the issue.

## Out of scope

- The retired self-hosted runner and its env file (Infra, DS-6324): no longer used by CI.
