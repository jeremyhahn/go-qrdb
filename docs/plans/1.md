# Plan: sealed SDK node ceremony CA (row 1)

## Objective

A shamir-sealed node embedded through sdk/go/node (NewStandaloneNode,
NewClusteredNode) must let officers register while sealed. The embedder's
`server.WithCeremonyCA` CA has to reach the sealed ceremony service built
by `lifecycle.BuildSealServicesOnly`, as it does in qrdbd. Otherwise the
registration fails with "ceremony: CA not initialized".

## Finding on this base

The wiring the brief asks for is already on main:
`server.CryptoOptions.CeremonyCA` exists, `ResolveCryptoOptions` fills it
from `WithCeremonyCA`, and `Node.withHolderInfra` copies it into
`lifecycle.Infra.CeremonyCA`. Both sealed `buildSealServices` calls
(standalone and clustered) go through that path. The consumer report most
likely comes from a qrdb pin that predates this wiring. This row adds the
missing regression coverage, so a future refactor cannot drop the
forwarding silently.

## Slices

1. Regression tests (sdk/go/node/sealed_ceremony_ca_test.go)
   - Standalone: a sealed shamir node with WithCeremonyCA registers an
     officer through the sealed ceremony service, and the certificate
     verifies under that CA.
   - Standalone control: with no CA, the registration returns
     `ceremony.ErrCANotInitialized`.
   - Clustered: a single-member in-process clustered node does the same.
   - Mutation check: with the `infra.CeremonyCA` assignment removed, both
     constructor tests fail with "ceremony: CA not initialized".
   - sealed_window_mount_test.go: newSealedHost passes WithCeremonyCA
     instead of calling `core.SetCA`, and the stale comment that said the
     SDK has no such option is removed.

## Gates

Touched-package unit tests (sdk/go/node, -race) and gofmt.

## Out of scope

- Any production behaviour change (the wiring already exists).
- Bumping or tagging the qrdb version the consumer pins.
