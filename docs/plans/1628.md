# Plan: row rolling-upgrades (#1628), lane RU-1a (#1634)

Objective: SPEC row rolling-upgrades clauses (1)-(3): a node announces its
SemVer release version, accepts only adjacent releases (engineering note Q1)
and refuses a peer outside that range with a typed error naming both
versions; QUIC refuses with the TLS no_application_protocol alert (120).

## Slices, in order

1. `pkg/release`: `Version()` (stamped by `-X ...pkg/release.version`),
   SemVer parser, `Adjacent`, `Check`, `*GapError`. Makefile and Dockerfile
   stamp it; `qrdbd version` prints it.
   Tests: TestAdjacent, TestCheck_DevAccepts, TestGapError_NamesBothVersions.
2. Announcement: `cluster.Member.ReleaseVersion` set beside `Features`;
   `featuregate.Gate.AdmitReplica` refuses a gap (Channel raft-membership).
   Tests: TestAdmitReplica_RefusesVersionGap,
   TestAdmitReplica_AcceptsAdjacentAndUnannounced.
3. Enrolment: `JoinRequest`/`JoinResponse.ReleaseVersion`; HandleJoinRequest
   checks the version before the token is consumed; joiners return a typed
   `*release.GapError`; errclass maps it to FailedPrecondition.
   Tests: TestHandleJoinRequest_RefusesVersionGapBeforeTokenConsumed,
   TestJoinCSR_GapRefusalIsTyped (Noise and HTTP joiners).
4. QUIC ALPN: `wire.Protocols` (current first, at most one previous);
   server pins NextProtos to it and logs both lists on a miss; forwarder and
   SDK offer it; SDK maps alert 120 (code 0x178) to `*protocolRefusedError`.
   Tests: TestQUICListener_RefusesGapProtocolWithAlert120,
   TestConnect_GapProtocolIsTypedRefusal.
5. Harness + CLI e2e: `qrdbdharness.WithReleaseVersion`;
   TestRollingUpgrade_EnrolmentAcrossVersions_CLI (T6) and
   TestRollingUpgrade_VersionGapRefused_CLI (T5, enrolment and ALPN legs).
6. Docs: docs/clustering/user.md "Upgrading a cluster", CHANGELOG.

## Changes beyond the plan

- `pkg/api/rest/server.go`: the join endpoint answers 409 (not 403) when the
  refusal carries the member's release, so a gap reads as FailedPrecondition.
- `cmd/qrdbd/cmd_test.go`: TestVersionVariables reads `release.Version()`
  now that `qrdbd`'s own `version` variable is gone.
- `release.SetForTesting`: lets tests in other packages run a stamped
  release in one process (a `go test` binary is Dev); production never calls
  it. clusterenroll adds the `joinerRelease` hook for the same reason.
- test/integration: `startSelfIssuedCAMultiProtocolCluster` is split into
  `startSelfIssuedCAFounders` (per-node binaries), `startJoiner` and
  `admitJoiner`, so the e2e runs a different stamped qrdbd per node and stops
  after a refused join. The cluster-CA anchor start helpers take the binary
  as a parameter.
