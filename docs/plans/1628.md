# Plan: SPEC row rolling-upgrades (#1628)

## Objective

Serve SPEC row rolling-upgrades clauses (1)-(4) and (6) on one row branch:
a node announces its SemVer release version, accepts only adjacent releases
(engineering note Q1) and refuses a peer outside that range with a typed
error naming both versions (QUIC with the TLS no_application_protocol alert
120); a mixed-version cluster (N and N+1) serves every transport, a new Raft
command is used only once every member supports it, a node rolls back
N+1 -> N before activation, and CI runs the N -> N+1 / N+1 -> N matrix as
CLI multi-protocol end-to-end tests.

## Slice RU-1 (issue #1634)

1. `pkg/release`: `Version()` (stamped by `-X ...pkg/release.version`),
   SemVer parser, `Adjacent`, `Check`, `*GapError`. Makefile and Dockerfile
   stamp it; `qrdbd version` prints it.
   Tests: TestAdjacent, TestCheck_DevAccepts, TestGapError_NamesBothVersions.
2. Announcement: `cluster.Member.ReleaseVersion` set beside `Features`;
   `featuregate.Gate.AdmitReplica` refuses a gap (Channel raft-membership).
   Tests: TestAdmitReplica_RefusesVersionGap,
   TestAdmitReplica_AcceptsAdjacentAndUnannounced.
3. Enrolment: `JoinRequest`/`JoinResponse.ReleaseVersion`; HandleJoinRequest
   checks the version before the token is consumed; joiners return a typed
   `*release.GapError`; errclass maps it to FailedPrecondition.
   Tests: TestHandleJoinRequest_RefusesVersionGapBeforeTokenConsumed,
   TestJoinCSR_GapRefusalIsTyped (Noise and HTTP joiners).
4. QUIC ALPN: `wire.Protocols` (current first, at most one previous);
   server pins NextProtos to it and logs both lists on a miss; forwarder and
   SDK offer it; SDK maps alert 120 (code 0x178) to `*protocolRefusedError`.
   Tests: TestQUICListener_RefusesGapProtocolWithAlert120,
   TestConnect_GapProtocolIsTypedRefusal.
5. Harness + CLI e2e: `qrdbdharness.WithReleaseVersion`;
   TestRollingUpgrade_EnrolmentAcrossVersions_CLI (T6) and
   TestRollingUpgrade_VersionGapRefused_CLI (T5, enrolment and ALPN legs).
6. Docs: docs/clustering/user.md "Upgrading a cluster", CHANGELOG.

Changes beyond the plan:

- `pkg/api/rest/server.go`: the join endpoint answers 409 (not 403) when the
  refusal carries the member's release, so a gap reads as FailedPrecondition.
- `cmd/qrdbd/cmd_test.go`: TestVersionVariables reads `release.Version()`
  now that `qrdbd`'s own `version` variable is gone.
- `release.SetForTesting`: lets tests in other packages run a stamped
  release in one process (a `go test` binary is Dev); production never calls
  it. clusterenroll adds the `joinerRelease` hook for the same reason.
- test/integration: `startSelfIssuedCAMultiProtocolCluster` is split into
  `startSelfIssuedCAFounders` (per-node binaries), `startJoiner` and
  `admitJoiner`, so the e2e runs a different stamped qrdbd per node and stops
  after a refused join. The cluster-CA anchor start helpers take the binary
  as a parameter.

## Slice RU-4a (issue #1635)

1. Synthetic N+1 behind the test-only build tag `qrdb_upgrade_probe`
   (never in DefaultBuildTags, the Makefile tag sets or a release build):
   - featuregate: `UpgradeProbe` feature added to `supported`;
   - protocol: `OpUpgradeProbe = 0xF0` reserved (MVCC put payload);
   - store: tagged builds apply the opcode as an MVCC put, untagged
     builds refuse it as an unknown opcode (UnknownOpError, encoded into
     the result as an absent capability), as an N binary does;
   - service: KVService.Put (the CLI's pebble path) and MVCCKVService.Put
     rewrite puts of `upgrade-probe/` keys to OpUpgradeProbe only once the
     cluster feature gate enables it.
   Tests: pkg/service/upgrade_probe_test.go, pkg/store/upgrade_probe_test.go
   and its untagged twin.
2. Clusterproof per-node image: inventory Node.Image (empty = the
   inventory image), Inventory.ImageOf, Cluster.Replace keeping the data
   volume. Tests: TestInventoryNodeImageOverride,
   TestReplaceKeepsDataVolume, TestStartUsesPerNodeImage (fake runner).
3. Per-node binaries in the integration suite: upgradeBinaries,
   startUpgradeCluster, (*upgradeCluster).roll, awaitActivated.
4. CLI multi-protocol e2e (no sleeps), mapped under INTTEST_clustering:
   - T1 TestRollingUpgrade_RollForward_CLI: 3xN rolled one node at a time
     to N+1 under a writer over every transport; every acked key reads
     back on every node over every transport after each roll; activation
     after the third roll; `upgrade-probe/after` applies everywhere.
   - T3 TestRollingUpgrade_RollBackBeforeActivation_CLI: one node to N+1,
     mixed-phase writes, no activation, roll back to N, all keys read back.

## Codex round 2 (PR #1638)

1. Each member's gate records its release under
   `__sys:cluster/features/releases/{replicaID}/{release}`; an offline
   committed member is compared by its recorded release, and a member with
   neither a live nor a recorded release refuses the joiner
   (UnknownMemberReleaseError). Tests: OfflineMemberReleaseIsKept,
   UnknownMemberReleaseRefuses, RecordsOwnRelease.
2. A candidate's release is compared only with committed system-shard
   members, never with other pre-membership advertisements. Test:
   PreMembershipCandidatesDoNotBlockEachOther.
3. T1 holds each rolled node down until the writer has acknowledged
   writes that started and finished while it was stopped.

## Codex round 3 (PR #1638)

1. Release admission returns the configuration change ID of the
   system-shard membership it compared against (Gate.AdmitReplicaAt);
   AdminService.AddMember passes it as the add's configChangeIndex, so
   go-quicraft refuses the add as stale when another membership change
   committed after admission. On that refusal it admits once more against
   the new configuration and retries once. Other shards keep 0. Tests:
   AddMemberReleaseAdmissionBindsTheCheckedConfiguration (0.58 and 0.60
   racing into an all-0.59 cluster), AddMemberReleaseAdmissionRetriesOnceOnStale,
   AdmitReplicaAtBindsOnlyTheSystemShard.
2. AdminService.AddObserverMember is bound the same way (requestAddObserver):
   an observer addition paused after admission is refused stale when a
   voter addition commits in between, re-admitted and retried once. Tests:
   AddObserverMemberReleaseAdmissionBindsTheCheckedConfiguration (0.58
   observer racing a 0.60 voter), AddObserverMemberReleaseAdmissionRetriesOnceOnStale.
4. Restart check (#1638 Codex P1): admission sees only additions, so Gate.Start
   refuses a committed member whose binary is not adjacent to the release it
   last recorded or to another member's (release.GapError, raft-membership),
   before it records its release. Tests: StartRefusesExistingMemberRestartAcrossAGap
   (0.58 member restarted on 0.60 in a 0.59 cluster),
   StartAcceptsExistingMemberRestartOnTheNextRelease (0.58 to 0.59).
   The ConfigChangeID-at-proposal P1 needs go-quicraft and is escalated.
8. #1638 Codex round 1: an unreadable release history (local, then via the
   leader) or membership refuses the restart instead of reading as empty
   (StartUnreadableReleaseHistoryRefusesRestart,
   StartUnreadableMembershipRefusesRestart); a restart release gap is kept
   in Gate.Refusal, terminal for the embedded node's start loop and
   reported by HostAdapter.HealthCheck.
9. #1638 Codex P1 3: a major boundary admits only the last minor of M
   declared in pkg/release lastMinor (empty: no major has shipped), so an
   older minor of M and an undeclared boundary are refused
   (TestAdjacent_MajorBoundary).
10. #1638 Codex round 3: a node whose state machine has no leases boots without
   the advertisement and so never ran Gate.Start; Gate.EnforceRelease runs
   the restart release check and record there too
   (TestStartFeatureGate_LeaselessNodeEnforcesTheReleaseGap).
11. #1638 Codex round 4: T2 covers the SQL wires. startUpgradeCluster serves
   MySQL and PostgreSQL on every node; in both mixed shapes a row inserted
   over each wire on every node reads back on every node over both wires, and
   in both leadership directions a follower's SQL insert is forwarded to the
   other release's leader (rolling_upgrade_sql_wire_test.go).
