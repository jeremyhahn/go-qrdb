# Plan: SPEC row rolling-upgrades (#1628)

## Objective

Serve SPEC row rolling-upgrades clauses (4) and (6): a mixed-version
cluster (N and N+1) serves every transport, a new Raft command is used
only once every member supports it, a node rolls back N+1 -> N before
activation, and CI runs the N -> N+1 / N+1 -> N matrix as CLI
multi-protocol end-to-end tests.

## Slice RU-4a (this lane, issue #1635)

1. Synthetic N+1 behind the test-only build tag `qrdb_upgrade_probe`
   (never in DefaultBuildTags, the Makefile tag sets or a release build):
   - featuregate: `UpgradeProbe` feature added to `supported`;
   - protocol: `OpUpgradeProbe = 0xF0` reserved (MVCC put payload);
   - store: tagged builds apply the opcode as an MVCC put, untagged
     builds refuse it as an unknown opcode (UnknownOpError, encoded into
     the result as an absent capability), as an N binary does;
   - service: KVService.Put (the CLI's pebble path) and MVCCKVService.Put
     rewrite puts of `upgrade-probe/` keys to OpUpgradeProbe only once the
     cluster feature gate enables it.
   Tests: pkg/service/upgrade_probe_test.go, pkg/store/upgrade_probe_test.go
   and its untagged twin.
2. Clusterproof per-node image: inventory Node.Image (empty = the
   inventory image), Inventory.ImageOf, Cluster.Replace keeping the data
   volume. Tests: TestInventoryNodeImageOverride,
   TestReplaceKeepsDataVolume, TestStartUsesPerNodeImage (fake runner).
3. Per-node binaries in the integration suite: upgradeBinaries,
   startUpgradeCluster, (*upgradeCluster).roll, awaitActivated.
4. CLI multi-protocol e2e (no sleeps), mapped under INTTEST_clustering:
   - T1 TestRollingUpgrade_RollForward_CLI: 3xN rolled one node at a time
     to N+1 under a writer over every transport; every acked key reads
     back on every node over every transport after each roll; activation
     after the third roll; `upgrade-probe/after` applies everywhere.
   - T3 TestRollingUpgrade_RollBackBeforeActivation_CLI: one node to N+1,
     mixed-phase writes, no activation, roll back to N, all keys read back.

## Slice RU-4b (issue #1636)

CLI multi-protocol e2e in rolling_upgrade_mixed_cli_test.go
(INTTEST_clustering); leadership moved by `qrdb admin member
transfer-leadership`:
- T2 MixedCluster: {N,N,next} and {N,next,next}; every node x transport
  writes and reads back everywhere; forwarding N+1->N and N->N+1 leader.
- T9 PreActivationGating: the probe put on N+1 takes the N path in both
  shapes; after the roll and activation it replicates everywhere.
- T4 OldBinaryRefusedAfterActivation: N on an activated data dir exits
  with UnsupportedFeatureError; the node rejoins on N+1.
- T7 KeyDeliveryAcrossVersions: {N,next,next} on startIsolationRaftCluster
  (extracted from TestIsolationRaft_EndToEnd); raft tenants created with
  the leader on N, then N+1, are served on every node under its own key.
