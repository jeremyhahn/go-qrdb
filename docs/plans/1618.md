# #1618: durable disk/fast state machines, test-only QRDB_NOSYNC_WRITES

## Objective

Close the three production-reachable switches that turn durability off:

- `DiskAdapter.Sync()` returned nil without syncing. The Raft engine calls
  `Sync()` on an on-disk state machine before it compacts the log, so a
  no-op Sync over a NoSync Pebble store let the log be compacted past
  applied state that was never made durable: a crash lost acknowledged
  writes in Raft mode.
- The disk and fast state machines open Pebble with `SyncWrites` false.
  That is correct only once `Sync()` really syncs.
- `QRDB_NOSYNC_WRITES=1` disabled the Raft WAL fdatasync in any build.

## Slices (tests first)

1. `PebbleStorage.Sync()` implements `storage.Syncer`: it syncs the WAL
   (`LogData(nil, pebble.Sync)`), or flushes the memtables when the WAL is
   disabled. `DiskAdapter.Sync()` calls the store's `Syncer` and returns its
   error wrapped as a `StorageError`.
   The WAL mode is the database's own: a store over a database opened
   elsewhere (`NewFromDB`) learns it from Pebble's refusal of the synced
   record and flushes from then on (Codex round 1).
   Tests, on Pebble's crashable in-memory FS (a crash clone keeps only
   synced data): a write, then Sync, survives a crash with the WAL on and
   off, for `New` and `NewFromDB`; a write never synced is lost; the
   last-applied index (`diskMetaKeyLastApplied`) survives a crash only after
   `DiskAdapter.Sync`; an injected WAL fsync failure never yields a
   successful Sync (Pebble makes it fatal); Sync reaches the store's
   `Syncer` and returns its error, including a real Pebble error (closed
   store). Each crash test fails against a no-op Sync.
2. `registry.go`: no edit. Its non-test path opens the store with
   `pebblestore.DefaultConfig`, which #1617 makes durable (`SyncWrites`
   true); with slice 1, `DiskAdapter.Sync` makes the store durable before
   Raft compacts the log whatever `SyncWrites` says.
3. `sdk/go/node`: `nosync_testbuild.go` (`qrdb_testonly`) honours
   `QRDB_NOSYNC_WRITES`; `nosync_prod.go` ignores it and logs one warning.
   Test (prod build): with the variable set, `NoSyncWAL` is false.
   No Makefile target, script or compose file sets the variable today, so
   no run needs the new tag.
4. CHANGELOG.md entry under Fixed. No doc names the variable.

## Out of scope

- `pkg/storage/pebble/config.go` defaults (issue #1617).
- Other state machine types and the Raft WAL configuration itself.
